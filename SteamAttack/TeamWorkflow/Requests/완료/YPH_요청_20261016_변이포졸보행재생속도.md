## 1. 한 줄 요약

기존 이동 수치를 유지한 채 걷기·뛰기 클립의 재생 속도를 보정할 수 있도록 작업 범위를 확인해 주세요. 이번 요청은 다른 작업자 영역 문제가 아니라, 사용자가 지정한 “Controller에는 클립만 연결” 제한을 넘는 변경입니다. 현재는 적용하지 않았습니다.

## 2. 대상 파일

| 경로 | 종류 | 수정 방식 |
|---|---|---|
| `Assets/Animations/YPH/Enemy/MutantSoldier/YPH_MutantSoldier.controller` | Controller | 승인 후 Locomotion Blend Tree의 Walk·Run 재생 배율만 조정 검토 |

## 3. 왜 필요한가

E1-b의 발 미끄러짐 없는 이동 조건을 검사했습니다. Humanoid 모델에서 클립을 120Hz로 샘플링하고, 발끝이 최저 높이에서 2cm 이내이며 뒤로 움직이는 구간을 접지 표본으로 잡았습니다. 기존 속도로 직진한다고 가정하면 다음 잔여 발속도가 계산됩니다.

| 클립 | 접지 표본 | 기존 이동 속도 | 원본 보폭 속도 평균 | 잔여 발속도 절댓값 평균 |
|---|---:|---:|---:|---:|
| Walk01_Forward | 93 | 1.5m/s | 1.999m/s | 0.499m/s |
| Run01_Forward | 46 | 3.5m/s | 3.945m/s | 0.463m/s |

이는 클립 표본 비교이며 실제 회전·가감속·Blend Tree 혼합은 포함하지 않은 추정입니다. 루트 이동은 0m이고 반복 경계의 발 위치 차이는 최대 약 0.0000003m라, 반복 때 몸이 출발점으로 끌려가는 문제와는 별개입니다.

## 4. 현재 상태 → 원하는 상태

- **현재:** 상태·파라미터·전환·재생 배율을 그대로 두고 클립만 연결했습니다. 발이 바닥에서 미끄러질 여지가 남습니다.
- **원하는 모습:** 전투·이동 수치를 유지하고 보행 보폭과 실제 이동 거리를 맞춥니다.

## 5. 구체적인 변경 방법

1. 재생 배율 변경을 허용할지 사용자에게 결정받습니다. 확정 전에는 Controller를 고치지 않습니다.
2. 허용한다면 Locomotion의 걷기 Child Motion Time Scale 약 `1.5 / 1.999 = 0.750`, 뛰기 약 `3.5 / 3.945 = 0.887`을 첫 비교값으로 사용합니다. 확정 수치가 아닙니다.
3. 기존 Speed 임계값 0/0.5/1·상태·파라미터·전환·EnemyMotor 속도는 유지합니다.
4. 실제 직진·회전·가감속 장면에서 확인한 뒤 배율을 확정합니다. 코드 수정이나 IK 추가는 제안 범위에 없습니다.

## 6. 영향 범위

- 이 Controller를 사용하는 `YPH_MutantSoldier.prefab`과 배치된 시험 적 두 마리.
- 공격·경직·사망 클립 속도에는 적용하지 않습니다.
- 씬·프리팹 작업자: YPH. 현재 Codex가 E1-b를 연결한 상태입니다.
- NGH 파일·Main·BossArena 저장은 필요하지 않습니다.

## 7. 확인 방법

`YPH_MainPlayerTest`에서 직선 배회·추적 때 접지 발이 밀리는지 확인하고, 멈춤·회전·Blend Tree 전환도 비교합니다. 타격 이벤트와 피해·받아치기를 회귀 검사합니다.

## 8. 안 하면 생기는 문제 / 대안

- **안 하면:** 전투는 가능하지만 E1-b의 발 미끄러짐 없음 조건은 충족했다고 볼 수 없습니다.
- **대안:** 원본 클립을 유지한 임시 연출로 사용하고 D1 조정 때 결정합니다. 전투 이동 수치를 임의로 변경하지 않습니다.

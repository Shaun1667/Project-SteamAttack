## 1. 한 줄 요약

받아치기를 YPH 폴더에 구현하고, D-081 절차로 `NGH_Player` 프리팹에 붙인 뒤 `Prefabs/NGH/`로 반환했습니다. NGH는 이번 변경을 병합하는 같은 작업에서 공용 씬에 남은 옛 `NGH.PlayerParry`·`NGH.ParryRingUI`를 정리하고 옛 스크립트 3개를 지운 다음, 새 받아치기의 성공·실패 신호에 패링 모션을 연결해 주세요.

## 3. 왜 필요한가

2026-10-15 회의에서 받아치기 담당이 바뀌었습니다(D-065). YPH가 플레이어 패링과 적 공통 인터페이스까지 구현하고, 플레이어 프리팹을 패링 가능한 상태로 NGH에게 넘깁니다. NGH는 넘겨받은 뒤 근접 전투·패링 모션을 맡습니다.

기존 `NGH.PlayerParry`는 지금 기획과 맞지 않아 다시 구현하기로 했습니다(D-066). 맞지 않는 부분은 다음과 같습니다.
- 성공 시 증기 +20, 시도 비용은 스크립트 기본 20·현재 두 공용 씬 저장 값 10입니다. 지금 기획은 성공해도 증기 변화가 없고, 화승총 발사 비용만 따로 냄(D-067)
- 성공 보상은 적 경직과 강공격 기회뿐입니다(D-068). R1에서 적의 다음 피해 증가 처리는 제거했습니다
- 적 AI만 대상으로 찾아서 현무를 받아칠 수 없음

Main·BossArena 씬은 `NGH_Player` 프리팹을 씁니다. 받아치기 작업 동안 YPH가 이 프리팹의 소유를 가져와 새 받아치기를 붙입니다(D-081). 그런데 두 씬 파일에도 옛 컴포넌트 참조가 남아 있습니다. 그대로 두면 옛 코드와 새 코드가 **둘 다 Ctrl에 반응**할 수 있습니다.

## 5. 구체적인 변경 방법

**순서가 중요합니다.** 옛 스크립트를 지우기 전에 씬에서 먼저 떼야 Missing Script가 남지 않습니다.

1. YPH가 D-081에 따라 새 받아치기를 부착하고 `Assets/Prefabs/NGH/NGH_Player.prefab`으로 반환했습니다. GUID는 `d37cef2ee2d00d7428d34aa83f41329e`입니다. 커밋·push·외부 알림은 이번 구현 요청에서 실행하지 않았습니다.
2. **YPH 브랜치를 병합할 때 같은 작업에서** Main·BossArena의 옛 `PlayerParry`와 별도 `ParryRingUI`를 제거합니다. 이후 Ctrl이 한 번만 처리되는지 확인합니다.
   - 두 씬에는 옛 PlayerParry가 따로 붙어 있습니다. NGH_Player 원본에는 없었습니다. 새 기능은 루트 `YPH.ParryController`, 자식 `ParryHUD/YPH.ParryRingView`에 있습니다.
   - 플레이어 인스턴스의 옛 컴포넌트 추가 오버라이드만 제거합니다. 새 Controller·HUD와 다른 설정은 보존합니다.
   - YPH_HeroPlayerIntegration의 옛 PlayerParry는 이번 R1에서 제거했습니다.
   - 사용자 승인으로 옛 ParryRingUI는 옛 PlayerParry가 없는 시작 씬에서 자동 등록을 생략하도록 최소 수정했습니다. 공용 씬의 옛 입력 제거를 대신하는 변경은 아닙니다.
3. NGH가 `PlayerParry.cs`, `ParryRingUI.cs`, `ParryRingConfig.cs`와 각 `.meta`를 지웁니다. `ParryRingConfig` 에셋이 있으면 같이 지웁니다.
4. NGH가 **환도를 들었을 때의** 패링 모션을 연결합니다(D-082). 화승총을 들었을 때의 모션은 YPH가 `YPH.RifleMotion`으로 따로 연결하므로, NGH 쪽은 `ParryAttempted`를 받았을 때 근접 무기를 든 경우에만 재생해 주세요. 기존 애니메이션 중 쓸 수 있는 것을 재사용합니다(D-066). 연결 위치는 기존처럼 `CombatBridge`를 추천합니다.

```csharp
// CombatBridge (NGH): parry는 NGH_Player 루트의 YPH.ParryController 인스턴스입니다.
private void OnEnable()  { if (parry != null) parry.ParryAttempted += HandleParry; }
private void OnDisable() { if (parry != null) parry.ParryAttempted -= HandleParry; }
private void HandleParry(bool success) => player.PlayParryMotion(success);
```

- 확정 신호: 인스턴스 `event Action<bool> ParryAttempted`와 `event Action<YPH.IParryTarget> TargetParried`. 성공 때 TargetParried가 먼저 발생하고 ParryAttempted(true)가 이어집니다. 실패는 ParryAttempted(false)만 발생하며 상태·쿨타임·시도 증기 부족으로 차단되면 둘 다 발생하지 않습니다.
- 받아칠 수 있는 상태인지(구르기·피격·사망 중 막기)는 YPH 쪽이 `PlayerController.CurrentAction`을 읽어 판단합니다. NGH 쪽은 추가할 것이 없습니다.
- YPH는 3번이 끝난 뒤 `YPH.EnemyAI`의 옛 API(`ActiveEnemies`, `ParryableAttackStarted`, `TryParry`)를 지웁니다. YPH가 먼저 지우면 옛 `PlayerParry`가 컴파일되지 않습니다.

## 6. 영향 범위

- 이 파일을 참조하는 곳: 옛 `PlayerParry`·`ParryRingUI`를 참조하는 다른 스크립트는 없음(2026-10-16 YPH 브랜치 기준 확인)
- 같이 영향받을 수 있는 다른 작업자·기능
  - 일반 적(YPH, 옛 API 정리)
  - 현무(BHS, 별도 요청 `BHS_요청_20261015_현무받아치기규약구현.md`)
- 씬·프리팹: Main, BossArena_Hyangwonjeong(NGH). `NGH_Player`는 받아치기 작업 동안 YPH가 고치고 돌려줌(D-081)

## 7. 확인 방법

1. Main에서 Ctrl을 한 번 누르면 받아치기가 한 번만 일어남 (동심원 한 쌍, 기본 설정에서는 증기 변화 없음)
2. 콘솔에 Missing Script 경고가 없음
3. 변이 포졸 내려치기를 받아치면 패링 모션이 나오고, 포졸이 경직됨
4. 타이밍이 틀리면 실패 모션(또는 모션 없음)이 나오고 피해를 정상으로 받음
5. BossArena에서도 1~2번이 같음

## 8. 안 하면 생기는 문제 / 대안

- **안 하면:** 옛 코드와 새 코드가 함께 Ctrl에 반응함. 옛 입력의 증기 소모·성공 회복이 섞이거나 동심원이 두 개 뜸. 적의 피해 증가는 R1에서 이미 제거됨
- **대안:** 옛 컴포넌트를 씬에서 비활성화만 하고 스크립트 삭제는 10/19 이후로 미룸. 이 경우 YPH의 옛 API 정리도 같이 미뤄짐

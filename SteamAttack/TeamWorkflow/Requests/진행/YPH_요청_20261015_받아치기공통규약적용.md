## 1. 한 줄 요약

받아치기는 YPH가 YPH 폴더에 새로 만들고, 작업 동안 `Prefabs/YPH/`로 옮겨 온 `NGH_Player` 프리팹에 붙인 뒤 `Prefabs/NGH/`로 되돌려 드립니다(D-081). NGH는 프리팹을 돌려받은 뒤 공용 씬에 남은 옛 `NGH.PlayerParry`·`NGH.ParryRingUI`를 정리하고 옛 스크립트 3개를 지운 다음, 새 받아치기의 성공·실패 신호에 패링 모션을 연결해 주세요.

## 3. 왜 필요한가

2026-10-15 회의에서 받아치기 담당이 바뀌었습니다(D-065). YPH가 플레이어 패링과 적 공통 인터페이스까지 구현하고, 플레이어 프리팹을 패링 가능한 상태로 NGH에게 넘깁니다. NGH는 넘겨받은 뒤 근접 전투·패링 모션을 맡습니다.

기존 `NGH.PlayerParry`는 지금 기획과 맞지 않아 다시 구현하기로 했습니다(D-066). 맞지 않는 부분은 다음과 같습니다.
- 성공 시 증기 +20, 시도 시 −10을 씀. 지금 기획은 성공해도 증기 변화가 없고, 화승총 발사 비용만 따로 냄(D-067)
- 약점 노출을 줌. 지금 기획은 적 경직과 강공격 기회만 줌(D-068)
- 적 AI만 대상으로 찾아서 현무를 받아칠 수 없음

Main·BossArena 씬은 `NGH_Player` 프리팹을 씁니다. 받아치기 작업 동안 YPH가 이 프리팹의 소유를 가져와 옛 컴포넌트를 새 받아치기로 바꿔 끼웁니다(D-081). 그런데 두 씬 파일에도 옛 컴포넌트 참조가 남아 있습니다. 그대로 두면 옛 코드와 새 코드가 **둘 다 Ctrl에 반응**할 수 있습니다.

| 항목 | 현재 | 원하는 모습 |
|---|---|---|
| 받아치기 코드 | `NGH.PlayerParry`, `NGH.ParryRingUI`, `NGH.ParryRingConfig` | YPH 폴더의 새 받아치기 하나 |
| `NGH_Player` 프리팹 | 옛 컴포넌트 | 새 받아치기 (YPH가 작업 후 돌려줌) |
| Main·BossArena 씬 | 옛 컴포넌트 참조가 남아 있음 | 옛 컴포넌트 없음. 플레이어는 돌려받은 프리팹 기준 |
| 패링 모션 | 없음 | 새 받아치기의 성공·실패 신호를 받아 `PlayerController`가 모션 재생 |

## 5. 구체적인 변경 방법

**순서가 중요합니다.** 옛 스크립트를 지우기 전에 씬에서 먼저 떼야 Missing Script가 남지 않습니다.

1. YPH가 `NGH_Player` 프리팹을 `Prefabs/YPH/`로 옮겨 옛 컴포넌트를 새 받아치기로 바꾸고, `Prefabs/NGH/`로 되돌려 커밋한 뒤 NGH에게 알립니다. 커밋할 때 성공·실패 신호 이름을 디스코드에 공유합니다. 이때까지 NGH는 이 프리팹을 고치지 않습니다(D-081).
2. NGH가 Main·BossArena 씬에 남은 옛 `PlayerParry`·`ParryRingUI`를 정리합니다.
   - 플레이어 인스턴스의 오버라이드는 되돌리고, 따로 붙은 UI 오브젝트가 있으면 지웁니다.
3. NGH가 `PlayerParry.cs`, `ParryRingUI.cs`, `ParryRingConfig.cs`와 각 `.meta`를 지웁니다. `ParryRingConfig` 에셋이 있으면 같이 지웁니다.
4. NGH가 패링 모션을 연결합니다. 기존 애니메이션 중 쓸 수 있는 것을 재사용합니다(D-066). 연결 위치는 기존처럼 `CombatBridge`를 추천합니다.

```csharp
// CombatBridge (NGH): YPH 받아치기의 신호를 받아 플레이어 모션으로 넘김. 신호 이름은 YPH 커밋으로 확정
private void OnEnable()  { if (parry != null) parry.ParryAttempted += HandleParry; }
private void OnDisable() { if (parry != null) parry.ParryAttempted -= HandleParry; }
private void HandleParry(bool success) => player.PlayParryMotion(success);
```

- 받아칠 수 있는 상태인지(구르기·피격·사망 중 막기)는 YPH 쪽이 `PlayerController.CurrentAction`을 읽어 판단합니다. NGH 쪽은 추가할 것이 없습니다.
- YPH는 3번이 끝난 뒤 `YPH.EnemyAI`의 옛 API(`ActiveEnemies`, `ParryableAttackStarted`, `TryParry`)를 지웁니다. YPH가 먼저 지우면 옛 `PlayerParry`가 컴파일되지 않습니다.

## 6. 영향 범위

- 이 파일을 참조하는 곳: 옛 `PlayerParry`·`ParryRingUI`를 참조하는 다른 스크립트는 없음(2026-10-16 YPH 브랜치 기준 확인)
- 같이 영향받을 수 있는 다른 작업자·기능
  - 일반 적(YPH, 옛 API 정리)
  - 현무(BHS, 별도 요청 `YPH_요청_20261015_현무받아치기규약구현.md`)
- 씬·프리팹: Main, BossArena_Hyangwonjeong(NGH). `NGH_Player`는 받아치기 작업 동안 YPH가 고치고 돌려줌(D-081)

## 7. 확인 방법

1. Main에서 Ctrl을 한 번 누르면 받아치기가 한 번만 일어남 (동심원 한 쌍, 증기 한 번만 변함)
2. 콘솔에 Missing Script 경고가 없음
3. 변이 포졸 내려치기를 받아치면 패링 모션이 나오고, 포졸이 경직됨
4. 타이밍이 틀리면 실패 모션(또는 모션 없음)이 나오고 피해를 정상으로 받음
5. BossArena에서도 1~2번이 같음

## 8. 안 하면 생기는 문제 / 대안

- **안 하면:** 옛 코드와 새 코드가 함께 Ctrl에 반응함. 증기가 두 번 바뀌거나 동심원이 두 개 뜨고, 옛 코드는 약점 노출을 계속 줌
- **대안:** 옛 컴포넌트를 씬에서 비활성화만 하고 스크립트 삭제는 10/19 이후로 미룸. 이 경우 YPH의 옛 API 정리도 같이 미뤄짐

## 9. 첨부

- 2026-10-16 개정: 10.15 회의 결정(D-065~D-068)과 프리팹 소유(D-081) 반영. 처음 요청("`PlayerParry`가 공통 규약으로 대상을 찾게 하고 증기 −10·+20, 판정 ±0.15초 적용")은 YPH 재구현으로 바뀌어 취소

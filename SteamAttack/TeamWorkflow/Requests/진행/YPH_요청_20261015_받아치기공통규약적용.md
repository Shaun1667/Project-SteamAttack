# 요청: PlayerParry·ParryRingUI가 받아치기 공통 규약으로 대상을 찾게 하고 기획 수치 반영

| 항목 | 내용 |
|---|---|
| 요청일 | 2026-10-15 |
| 요청자 | YPH |
| 받는 사람 | NGH |
| 우선순위 | 🔴 막힘 |
| 희망 기한 | 2026-10-17 (YPH 공통 규약 커밋 10/16 이후) |
| 관련 기획서 | `Design/전투/패링.md` (D-039, D-061) |
| 상태 | 요청됨 |

## 1. 한 줄 요약

`PlayerParry`와 `ParryRingUI`가 `YPH.EnemyAI` 대신 공통 규약(`YPH.IParryTarget`, `YPH.ParryTargets`)으로 받아칠 대상을 찾게 하고, 증기 소모·판정 창을 기획 수치로 맞춰 주세요.

## 2. 대상 파일

| 경로 | 종류 (스크립트/씬/프리팹/설정/기타) | 수정 방식 (추가/변경/삭제) |
|---|---|---|
| `Assets/Scripts/NGH/Player/PlayerParry.cs` | 스크립트 | 대상 검색·판정 창·증기 소모 변경 |
| `Assets/Scripts/NGH/Player/ParryRingUI.cs` | 스크립트 | 신호 구독·위치·상태 읽기 변경 |
| `ParryRingConfig` 에셋 또는 `PlayerParry` | 설정 | 판정 창 값 한 곳에 두기 |

## 3. 왜 필요한가

D-061로 받아치기 담당을 나눴습니다. 플레이어 쪽(입력·판정·동심원 UI·연출)은 NGH, 적 쪽과 공통 규약은 YPH, 현무는 BHS입니다. 지금 `PlayerParry.TryParryNearby()`는 `EnemyAI.ActiveEnemies`만 돌고, `ParryRingUI`는 `EnemyAI.ParryableAttackStarted`만 듣습니다. 그래서 기획의 받아칠 수 있는 공격 중 **현무의 흑철 찍기·뱀의 목 찌르기는 받아칠 수 없습니다**(공략 핵심: 받아치기 → 증기 → 증기발도). 공통 규약으로 바꾸면 현무(BHS)나 이후 적이 규약만 구현해도 NGH 코드를 다시 고칠 필요가 없습니다.

## 4. 현재 상태 → 원하는 상태

| 항목 | 현재 | 원하는 모습 (기획서) |
|---|---|---|
| 대상 목록 | `EnemyAI.ActiveEnemies` | `ParryTargets.Active` |
| 동심원 시작 신호 | `EnemyAI.ParryableAttackStarted` | `ParryTargets.AttackStarted` |
| 거리·동심원 위치 | `enemy.transform.position` (+ `bodyHeight`) | `target.ParryPoint` (창끝, 발톱 끝처럼 공격 지점) |
| 성공 처리 | `enemy.TryParry(...)`(적이 판정 창을 한 번 더 확인) | 판정은 `PlayerParry`가 하고 `target.ApplyParry(...)`로 처리만 맡김 |
| 판정 창 | `EnemyAI.ParryHalfWindow` 상수 ±0.15 | NGH 설정값 하나, ±0.15초(시연 빌드 ±0.2초). `PlayerParry`와 `ParryRingUI`가 같은 값을 씀 |
| 증기 소모 | 20 | **10** |
| 성공 시 증기 | 20 | 20 (그대로) |
| 자세 붕괴 표시 | `e.ai.CurrentState == EnemyAI.State.Parried` | `target.IsParryStunned` |

## 5. 구체적인 변경 방법

YPH가 10/16까지 아래 두 파일을 커밋합니다. `YPH.EnemyAI`도 이 규약을 구현하고, 기존 `ActiveEnemies`·`ParryableAttackStarted`·`TryParry`는 이 요청이 처리될 때까지 남겨 둡니다(어느 순서로 해도 컴파일이 깨지지 않음).

```csharp
// Assets/Scripts/YPH/Enemy/IParryTarget.cs
namespace YPH
{
    /// <summary>받아칠 수 있는 공격을 가진 대상(적·보스)이 지키는 약속.</summary>
    public interface IParryTarget
    {
        /// <summary>동심원을 그리고 거리를 재는 월드 위치 (예: 창끝, 발톱 끝)</summary>
        Vector3 ParryPoint { get; }
        /// <summary>지금 받아칠 수 있는 공격을 준비 중인가</summary>
        bool IsParryWindowOpen { get; }
        /// <summary>두 원이 겹치는 시각(Time.time 기준). 이 시각 ± 판정 창 안에 누르면 성공</summary>
        float ParryOverlapTime { get; }
        /// <summary>받아치기에 당해 자세가 무너진 상태인가 (동심원 성공 연출 유지용)</summary>
        bool IsParryStunned { get; }
        /// <summary>플레이어 쪽 판정이 성공했을 때 호출. 공격 취소·자세 붕괴·약점 노출 후 true. 창이 이미 닫혔으면 false</summary>
        bool ApplyParry(float damage, Vector3 from);
    }
}

// Assets/Scripts/YPH/Enemy/ParryTargets.cs
namespace YPH
{
    /// <summary>받아칠 수 있는 대상의 공용 목록과 "받아칠 수 있는 공격 시작" 신호.</summary>
    public static class ParryTargets
    {
        public static IReadOnlyList<IParryTarget> Active { get; }
        /// <summary>(대상, 두 원이 겹칠 때까지 남은 초)</summary>
        public static event System.Action<IParryTarget, float> AttackStarted;
        public static void Register(IParryTarget target);     // 대상의 OnEnable
        public static void Unregister(IParryTarget target);   // 대상의 OnDisable
        public static void NotifyAttackStarted(IParryTarget target, float secondsUntilOverlap);
    }
}
```

NGH 쪽 변경:

1. `PlayerParry.TryParryNearby()`의 대상 검색을 바꿉니다.

```csharp
IParryTarget best = null;
float bestDistance = float.MaxValue;
foreach (IParryTarget target in ParryTargets.Active)
{
    if (target == null || !target.IsParryWindowOpen) continue;
    float d = Vector3.Distance(target.ParryPoint, transform.position);
    if (d > parryRange) continue;
    if (Mathf.Abs(Time.time - target.ParryOverlapTime) > halfWindow) continue;   // halfWindow: NGH 설정값
    if (d < bestDistance) { bestDistance = d; best = target; }
}
bool success = best != null && best.ApplyParry(parryDamage, transform.position);
```

2. `DescribeMiss()`도 같은 목록과 `ParryPoint`를 씁니다.
3. `steamCost` 기본값을 20 → **10**으로 바꿉니다. 씬에 저장된 값이 20이면 인스펙터 값도 10으로 바꿉니다.
4. 판정 창 `halfWindow`(기본 0.15, 시연 빌드 0.2)를 한 곳(예: `ParryRingConfig`)에 두고 `PlayerParry`·`ParryRingUI`가 같이 읽습니다.
5. `ParryRingUI`:
   - `EnemyAI.ParryableAttackStarted` 구독을 `ParryTargets.AttackStarted`로 바꿉니다.
   - `Entry.ai`(EnemyAI)를 `IParryTarget`으로 바꿉니다.
   - 위치 계산을 `target.ParryPoint`로 바꿉니다.
   - `CurrentState == Parried` 검사를 `target.IsParryStunned`로 바꿉니다.
   - 대상이 꺼졌는지는 `(target as Object) == null`로 확인합니다.

## 6. 영향 범위

- 이 파일을 참조하는 곳: `ParryRingUI`가 `PlayerParry.ParryAttempted`를 구독(변경 없음)
- 같이 영향받을 수 있는 다른 작업자·기능: 일반 몬스터(YPH, 규약 구현), 현무(BHS, 별도 요청 `YPH_요청_20261015_현무받아치기규약구현.md`)
- 씬·프리팹이면: `PlayerParry` 인스펙터의 `steamCost` 값 확인

## 7. 확인 방법

1. 변이 포졸 내려치기 → 창끝에 동심원 → 겹칠 때 Ctrl → 성공, 증기 −10 후 +20
2. 겹침보다 0.3초 일찍 Ctrl → 실패, 증기 −10, 공격이 그대로 들어옴
3. 현무가 규약을 구현한 뒤: 흑철 찍기 발톱 끝에 동심원 → 받아치기 성공
4. Play 두 번 연속 실행해도 동심원이 두 번 뜨거나 남지 않음

## 8. 안 하면 생기는 문제 / 대안

- **안 하면:** 현무를 받아칠 수 없어서 보스전 공략 순서(받아치기 → 증기 +20 → 증기발도)가 성립하지 않음
- **대안:** 없음. 현무를 `EnemyAI` 목록에 억지로 넣는 방법은 보스 구조와 맞지 않음

## 9. 첨부

- 관련 결정: D-039(받아치기 규칙), D-061(담당 경계)
- 판정 수치 근거: `Design/전투/패링.md` 3번 수치표
- 도메인 리로드가 꺼져 있어서 `ParryTargets`의 정적 목록·이벤트는 YPH가 Play 시작 시 초기화합니다(`RuntimeInitializeOnLoadMethod`). NGH 쪽은 지금처럼 `OnEnable`에서 구독, `OnDisable`에서 해제만 하면 됩니다

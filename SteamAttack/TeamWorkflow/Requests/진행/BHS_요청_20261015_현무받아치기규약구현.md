## 1. 한 줄 요약

현무의 받아칠 수 있는 공격(1페이즈 우선)에 `YPH.IParryTarget`을 구현하고 `YPH.ParryTargets`에 등록해 주세요. 받아치기에 성공하면 공격을 취소하고 현무를 경직시키기만 하면 됩니다. 약점 노출·피해 3배는 없습니다.

## 2. 대상 파일

| 경로 | 종류 (스크립트/씬/프리팹/설정/기타) | 수정 방식 (추가/변경/삭제) |
|---|---|---|
| `Assets/Scripts/BHS/Boss/` 의 현무 공격 스크립트 (예: `BossFSM`, `BossAttack`) | 스크립트 | `IParryTarget` 구현 추가 |
| 현무 프리팹 | 프리팹 | 받아칠 수 있는 공격 표시 |

`BossHealth`는 고치지 않아도 됩니다(약점 노출 제외, D-068).

## 3. 왜 필요한가

2026-10-15 회의에서 받아치기 대상을 **일반 적 강공격과 보스 일부 공격 패턴**으로 정했습니다(D-067). 받아칠 수 있는 공격의 예고 표시도 유지합니다(D-072).

지금 받아치기 대상은 `YPH.EnemyAI`뿐이라 현무는 받아칠 수 없습니다. 플레이어 쪽 받아치기는 YPH가 새로 만들고 있고(D-065), 대상은 `ParryTargets`로만 찾습니다. 그래서 현무가 규약만 구현하면 판정, 동심원 UI, 증기 처리는 플레이어 쪽이 맡고 BHS 코드는 다른 곳과 엮이지 않습니다.

## 4. 현재 상태 → 원하는 상태

| 항목 | 현재 | 원하는 모습 |
|---|---|---|
| 현무 받아치기 | 불가 | 받아칠 수 있는 공격 준비 중에 공격 지점에 동심원 → 겹칠 때 Ctrl → 공격 취소, 현무 경직 |
| 성공 보상 | — | 현무 경직. 그동안 플레이어가 강공격을 넣을 기회 (D-067) |
| 약점 노출·피해 3배 | — | **없음** (D-068) |
| 증기 | — | 현무 쪽은 처리하지 않음. 받아치기에 성공해도 증기 변화 없음 (D-067) |

## 5. 구체적인 변경 방법

규약 파일은 이미 YPH 브랜치에 있습니다(`Assets/Scripts/YPH/Enemy/IParryTarget.cs`, `ParryTargets.cs`).

```csharp
namespace YPH
{
    public interface IParryTarget
    {
        Vector3 ParryPoint { get; }          // 동심원 위치·거리 기준 (예: 내려찍는 발 끝)
        bool IsParryWindowOpen { get; }      // 받아칠 수 있는 공격 준비 중인가
        float ParryOverlapTime { get; }      // 두 원이 겹치는 시각 (Time.time 기준) = 공격이 닿는 시각
        bool IsParryStunned { get; }         // 받아치기에 당해 경직된 상태인가
        bool ApplyParry(float damage, Vector3 from);  // 판정 성공 후 호출. 공격 취소·경직 후 true, 창이 닫혔으면 false
    }

    public static class ParryTargets
    {
        public static void Register(IParryTarget target);    // OnEnable
        public static void Unregister(IParryTarget target);  // OnDisable
        public static void NotifyAttackStarted(IParryTarget target, float secondsUntilOverlap);  // 받아칠 수 있는 공격 준비 시작 때
    }
}
```

> `IParryTarget.ApplyParry` 주석에는 아직 "약점 노출"이 적혀 있습니다. YPH가 고칠 예정이니 무시해 주세요.

BHS 쪽에서 할 일입니다. 구조는 BHS 코드에 맞게 자유롭게 정해 주세요. 아래는 `BossAttack`의 준비 → 공격 → 회복 흐름에 맞춘 예시입니다.

1. 받아칠 수 있는 공격에 표시를 둡니다. 예: `BossAttack`에 `[SerializeField, Tooltip("...")] private bool _parryable;`
   - 1페이즈 우선(D-063). 추천은 **근접 내려찍기**입니다. 돌진·브레스처럼 넓게 덮치는 공격은 받아칠 수 없습니다.
2. 현무 쪽 한 곳(예: `BossFSM`)이 `IParryTarget`을 구현합니다. `OnEnable`에서 `ParryTargets.Register(this)`, `OnDisable`에서 `Unregister(this)`를 부릅니다.
3. 받아칠 수 있는 공격의 준비가 시작되면 아래처럼 처리합니다.
   - `IsParryWindowOpen = true`
   - `ParryOverlapTime` = 공격이 닿는 시각
   - `ParryTargets.NotifyAttackStarted(this, ParryOverlapTime - Time.time)` 호출
   - 판정 시각이 지나거나 공격이 끝나면 `IsParryWindowOpen = false`
4. `ParryPoint`는 지금 공격하는 부위의 월드 위치를 돌려줍니다.
5. `ApplyParry(damage, from)`이 불리면 아래처럼 처리하고 `true`를 돌려줍니다.
   - 진행 중인 공격의 `CancelAttack()`
   - 경직(`IsParryStunned = true`). 경직 시간은 플레이어 강공격이 들어갈 만큼, 인스펙터에서 조정
   - `damage`는 받아치기 사격의 피해입니다. 넣을지 말지는 BHS가 정해 주세요.
6. 공격 준비 시간·경직 시간은 인스펙터에 노출하고 한국어 툴팁을 답니다(D-072, 코드컨벤션 3-1).

참고 구현: `YPH.EnemyAI.ApplyParry`, `ForceParried` (약점 노출 부분은 빼고 보세요)

## 6. 영향 범위

- 이 파일을 참조하는 곳: 플레이어 받아치기(YPH)는 `ParryTargets`를 통해서만 읽음. BHS 코드를 직접 참조하지 않음
- 같이 영향받을 수 있는 다른 작업자·기능: 받아치기 모션(NGH, 별도 요청 `NGH_요청_20261015_받아치기공통규약적용.md`)
- 씬·프리팹: 현무 프리팹에서 받아칠 수 있는 공격 표시만

## 7. 확인 방법

1. 받아칠 수 있는 공격의 준비 중에 공격 지점에 흰 동심원이 뜸
2. 겹칠 때 Ctrl → 공격이 취소되고 현무가 경직됨
3. 경직 동안 플레이어 강공격이 들어감
4. 돌진·브레스에는 동심원이 뜨지 않음
5. 타이밍이 틀리면 공격이 그대로 들어옴

## 8. 안 하면 생기는 문제 / 대안

- **안 하면:** 보스전에서 받아치기 → 경직 → 강공격 흐름을 보여줄 수 없음
- **대안:** 없음. 현무를 `EnemyAI` 목록에 넣는 방법은 보스 구조와 맞지 않음

## 9. 첨부

- 2026-10-16 개정: 10.15 회의 결정(D-067, D-068, D-071, D-072) 반영. 처음 요청의 "증기 +20 → 증기발도로 가갑 파괴", "`BossHealth` 약점 노출 3초·피해 3배"는 취소
- 어느 패턴을 받아칠 수 있게 할지, 보스 공략 구조(다리·무릎과 넘어짐, 코어 공격)와 어떻게 이을지는 BHS가 정함(D-080)
- 받아치기 판정 허용 폭은 플레이어 쪽 설정(임시 ±1초). 회의록 `Meetings/2026-10-15_기능우선과받아치기규칙.md` 7번

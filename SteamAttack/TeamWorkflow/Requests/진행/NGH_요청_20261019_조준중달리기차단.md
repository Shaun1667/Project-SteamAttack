| 상태 | 요청됨 |

## 1. 한 줄 요약

화승총 조준 중에는 Shift 입력이 달리기 분기에 진입하지 않게 막아 주세요.

## 2. 대상 파일

| 경로 | 종류 | 수정 방식 |
|---|---|---|
| `Assets/Scripts/NGH/Player/PlayerController.cs` | 스크립트 | 달리기 허용 조건 추가 |
| `Assets/Scripts/NGH/Player/CombatBridge.cs` | 스크립트 | 조준 입력과 달리기 허용 조건 연결 |

## 3. 왜 필요한가

`PlayerController.Update`는 Shift만 읽어 `run`을 결정합니다. `CombatBridge.LateUpdate`가 조준 이동 배율을 적용해도 달리기 속도와 달리기 애니메이션을 선택한 뒤이므로 조준 중 달리기가 가능합니다. 단순히 이동 배율을 더 낮추면 달리기 동작은 남습니다.

## 4. 현재 상태 → 원하는 상태

- **현재:** 화승총 우클릭 조준 중 Shift를 누르면 달리기 분기를 사용합니다.
- **원하는 모습:** 조준 중에는 걷기 속도·애니메이션에 기존 조준 이동 배율을 적용합니다. 조준을 풀면 누르고 있던 Shift가 다시 작동합니다. 환도와 비조준 달리기는 유지합니다.
- 같은 사용자 요청의 구르기 중 조준 금지는 YPH `AimController`에서 처리합니다. 총 부모의 `PlayerController.CurrentAction`을 읽으며 NGH 파일은 수정하지 않습니다.

## 5. 구체적인 변경 방법

1. `PlayerController`의 기존 `ShotGate`와 같은 방식으로 `public Func<bool> SprintGate;`를 추가합니다. `run` 계산은 아래처럼 변경합니다. 연결하지 않은 플레이어는 기존 동작을 유지합니다.

```csharp
bool run = (kb.leftShiftKey.isPressed || kb.rightShiftKey.isPressed)
    && (SprintGate == null || SprintGate());
```

2. `CombatBridge`에서 현재 조준 입력 조건을 `WantsAim` 조회로 모읍니다. 기존 조건인 마우스 존재·사망 아님·조작 안내창 닫힘·`GunReady`·우클릭에 구르기 아님을 포함합니다. `aim != null && aim.isActiveAndEnabled`도 확인합니다.
3. `Update`의 `aim.SetAiming`에 `WantsAim`을 전달하고, `CanSprint()`는 `!WantsAim`을 반환합니다. `OnEnable`에서 `player.SprintGate = CanSprint`, `OnDisable`에서 자신이 연결한 콜백이면 해제합니다.
4. 지난 프레임의 `aim.IsAiming`만 읽으면 Shift와 우클릭을 동시에 누른 첫 프레임에 달리기가 들어갈 수 있습니다. 위 조회는 현재 입력을 직접 읽어 실행 순서에 의존하지 않게 합니다.

## 6. 영향 범위

- `PlayerController`를 사용하는 모든 플레이어. 미연결 상태에서는 기존 달리기 유지.
- `CombatBridge`를 사용하는 화승총의 조준 이동. 속도 수치, 카메라 감도, 구르기 이동, 피해 수치 변경 없음.
- 씬·프리팹·Animator 수정 불필요. NGH 담당자의 현재 작업과 병합 필요.

## 7. 확인 방법

`Assets/Scenes/YPH/YPH_MainPlayerTest.unity`에서 실제 키보드·마우스 입력으로 확인합니다.

1. 비조준 W+Shift는 기존 달리기 속도·애니메이션 사용.
2. 달리는 중 우클릭, 조준 중 Shift, 우클릭+Shift 동시 입력 모두 걷기로 전환. Animator `Speed`가 달리기 목표 1로 설정되지 않는지 확인.
3. 우클릭을 놓고 Shift를 유지하면 달리기 복귀. 좌우 Shift 각각 검사.
4. 조준 중 Space로 구르면 조준 해제, 구르기 종료까지 재조준 차단. 우클릭을 계속 누르면 종료 후 조준 복귀.
5. 환도·납도·무기 교체·조작 안내창·사망·연결부 비활성화 때 기존 동작과 콜백 정리를 확인.

## 8. 안 하면 생기는 문제 / 대안

- **안 하면:** 사용자 요청 중 조준 중 달리기 금지는 미완료입니다.
- **대안:** YPH에서 `runSpeed`나 Animator 값을 매 프레임 덮어쓰면 NGH 이동 결정과 충돌하므로 적용하지 않습니다. 사용자의 기존 “NGH 코드는 요청서로만 남기기” 지시와 `AI_지침.md` 4번에 따라 본 요청으로 남깁니다.

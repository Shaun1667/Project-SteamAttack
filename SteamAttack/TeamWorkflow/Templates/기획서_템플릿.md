# 기획서 템플릿

- 저장: `Design/분류/기능이름.md` (분류: `세계관/` · `전투/` · `성장/` · `적/` · `월드/` · `UI/`)
- 그림: `Design/images/기능이름_번호.확장자`
- 양식은 두 가지입니다. **`세계관/`은 B, 나머지 분류는 A**를 씁니다. 필요한 양식의 `---` 아래만 복사합니다.
- 해당 없는 칸은 `없음`으로 씁니다.
- 기획자·구현 담당·상태·관련 결정은 **문서 머리(📌)에만** 씁니다. [기능 표](../Design/README.md)는 `python Tools/check.py --write`가 머리 정보로 다시 만듭니다. 표를 손으로 고치지 않습니다.
- 이 문서는 **구현 담당이 고칩니다.** 구현 담당이 `미정`이면 NMJ가 고칩니다. 서기 YPH는 모든 기획서를 고칠 수 있습니다.
- 구현 방법(코드 구조, 스크립트 이름)은 쓰지 않습니다. 구현 계획은 `계획서_템플릿.md`, 완료 후 사용법은 `기능문서_템플릿.md`에 씁니다.

## 공통 규칙

- 정해지지 않은 것은 본문에 섞지 않고 `확인 필요` 칸에 모읍니다. "~하면 될 듯?", "~일지도" 같은 표현은 쓰지 않습니다.
- 다른 기획서와 겹치는 내용은 다시 쓰지 않고 링크만 겁니다. 예: 증기 소모량은 증기 시스템 기획서에만 쓰고, 다른 문서는 `[증기 시스템](../전투/증기시스템.md)`처럼 링크합니다.
- 결정이 바뀌면 본문을 고치고, `변경 이력`에 회의 결정 번호(`D-번호`)를 남깁니다.

## A. 기능 기획서 말투 (전투·성장·적·월드·UI)

개발자가 읽고 바로 만들 수 있게 **규칙과 수치만** 씁니다.

- 사실만 짧게 씁니다. 미사여구, 감탄, 수식어("매우", "자연스럽게", "효과적으로")는 쓰지 않습니다.
- 항목은 명사형이나 짧은 평서문으로 끝냅니다. 예: `구르기 중 0.5초 무적`, `증기 10 미만이면 사용 불가`.
- 규칙은 한 줄에 하나만 씁니다. 조건은 `~이면 ~한다` 형식으로 씁니다.
- 수치는 표로 씁니다. 정해지지 않은 수치는 `초기값`이라고 적고 언제 정할지를 같이 적습니다. 예: `초기값 2초, 플레이테스트 후 확정`.
- 이유는 `4. 근거`에만 씁니다.

## B. 세계관 기획서 말투 (세계관)

팀원이 같은 세계를 떠올리게 **설정을 이야기로** 씁니다. 그래도 꾸밈보다 사실이 먼저입니다.

- 설정은 세계 안의 사실처럼 **단정형 현재형**으로 씁니다. 예: `현무의 한 호흡은 5초다.` (`~라고 한다`, `~인 것 같다` 쓰지 않음)
- 문단으로 써도 됩니다. 한 문단에는 설정 하나만 담습니다.
- 분위기 묘사는 장소·인물 설명에 한두 문장만 씁니다. 장면 연출은 `6. 게임과의 연결`에 적습니다.
- 고유명사는 처음 나올 때 한자나 뜻을 같이 적습니다. 예: `허물 잔상(脫殼影, 탈각영)`. 이후에는 같은 이름만 씁니다.
- 세계의 규칙은 `2. 세계의 법칙`에 번호를 붙여 씁니다. 다른 칸에서는 `(→ 법칙 3)`처럼 번호로 가리킵니다.
- 모든 설정에는 **게임에서 무엇으로 보이는지**가 있어야 합니다. 게임에 안 나오는 설정은 `확인 필요`에 두거나 뺍니다.
- 설정끼리 어긋나면 본문에 둘 다 쓰지 않습니다. `8. 확인 필요`에 충돌로 적습니다.

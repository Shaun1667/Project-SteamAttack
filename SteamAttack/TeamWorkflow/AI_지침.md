# AI 작업 지침 (팀 공용)

팀원이 쓰는 모든 AI(Claude Code, Codex, ChatGPT 등)가 TeamWorkflow 문서와 코드 작업에서 따르는 규칙입니다. 경로는 `SteamAttack/TeamWorkflow/` 기준입니다. 사람이 읽어도 됩니다.

## 0. 시작 전

- **작업자 이니셜을 확인한다.** 각자의 개인 AI 설정(6번)에 적혀 있다. 모르면 묻는다. 이니셜: BHS, NGH, NMJ, YPH (CHG는 팀에서 빠짐)
- [README.md](README.md)의 **"정보는 한 곳에만 쓴다"** 표와 **기본 흐름**을 먼저 읽는다. 어떤 정보를 어느 문서에 쓰는지는 그 표가 기준이다.
- 답변·문서·주석·커밋 메시지는 한국어로 쓴다. 코드 식별자·경로·명령어·에러 원문은 그대로 쓴다.
- 작업이 끝나면 `python Tools/check.py --write`를 실행하고 **문제 0건**을 확인한다. 문제가 남으면 고치거나 사용자에게 보고한다.
- 커밋·push는 사용자가 시킬 때만 한다. 커밋 메시지는 [협업규칙](Rules/협업규칙.md) 2번 형식(`타입: 한국어 요약`)을 지킨다. TeamWorkflow 문서도 작업자 자기 브랜치에 커밋한다. 통합 흐름은 각자 브랜치 → NGH 브랜치에서 병합·확인 → `main`에 반영(D-060).
- 기획서·회의록의 원본은 노션이고 TeamWorkflow는 정제본이다(D-058). 개발과 AI 작업은 TeamWorkflow를 기준으로 한다.

## 1. 하지 말 것

- **고치지 않는 문서:** 날짜 회의록(`Meetings/YYYY-MM-DD_*.md`), `Design/_원문/`, `Design/_보관/`. 오타도 손대지 않는다.
- **손으로 고치지 않는 생성물:** `Design/README.md`의 기능 표 구역, `Meetings/현황.md`. `Tools/check.py --write`로만 만든다.
- **D-번호를 새로 만들지 않는다.** 결정 로그에 번호를 붙이는 일은 3-1 회의 반영(YPH)에서만 한다.
- **남의 기획서를 고치지 않는다.** 기획서 담당은 문서 머리(📌)의 `구현 담당`이고, `미정`이나 `-`이면 NMJ다. 고칠 필요가 있으면 사용자에게 보고한다.
- **추측해서 확정하지 않는다.** 정해지지 않은 것은 본문이 아니라 `확인 필요`에 쓴다. 받아쓰기에서 못 알아들은 내용은 `(확인 필요)`로 남긴다.
- **복사하지 않는다.** 다른 문서에 있는 내용은 다시 쓰지 않고 링크한다.

각 템플릿 위쪽의 말투·작성 규칙을 그대로 따른다.

## 3. 작업 절차

### 3-1. 회의 반영 (YPH)

입력: 회의 받아쓰기·메모, 또는 기획자가 통째로 써 온 기획안

1. 회의록을 회의록 템플릿으로 `Meetings/YYYY-MM-DD_제목.md`에 쓴다. 기획안이면 원문을 `Design/_원문/YYYY-MM-DD_이니셜_버전/`에 그대로 둔다.
2. 확정된 결정마다 [결정 로그](Meetings/README.md)의 마지막 번호 다음부터 D-번호를 붙이고, 로그에 한 줄씩 추가한다.
   - `반영 기획서`에는 고칠 문서를 링크한다. 기능이 아니면 `00_프로젝트.md`, 코드 규칙이면 `Rules/`. `미반영`은 쓰지 않는다.
   - 회의가 아닌 결정(사용자가 직접 정한 것)은 `회의록` 칸에 `결정자 확인 (YYYY-MM-DD)`을 쓴다. 예: `YPH 확인 (2026-10-14)`
   - 뒤집힌 옛 결정은 지우지 않고 상태를 `대체됨→D-새번호`로 바꾼다. 서로 맞지 않는 결정은 상태를 `확인 필요 (D-xxx와 충돌)`로 둔다.
3. 회의록 목록에 한 줄 추가한다 (최신이 위).
4. `00_프로젝트.md`는 YPH 담당이라 같이 고친다. **다른 기획서 본문은 고치지 않는다.**
5. `python Tools/check.py --write` → 문제 0건 확인.
6. 보고: 추가한 D-번호, 담당자별 반영 대기([Meetings/현황.md](Meetings/현황.md)), 받아쓰기가 불확실해 확인이 필요한 부분.

### 3-2. 내 기획서 반영 (각 담당)

입력: 작업자 이니셜

1. `python Tools/check.py --write` 후 `Meetings/현황.md`의 **반영 대기 > 내 이니셜** 목록을 본다.
2. 결정마다 출처(회의록 또는 `_원문/` 기획안)를 읽고 기획서 본문을 고친다.
3. 기획서 `변경 이력`에 `날짜 | D-번호 | 바뀐 내용`을 추가하고, 머리의 `관련 결정`·`상태`를 맞춘다.
4. 결정끼리 어긋나거나 근거가 부족하면 본문에 넣지 않고 `확인 필요`에 적는다.
5. `python Tools/check.py --write` → 문제 0건, 반영 대기에서 사라졌는지 확인.
6. 현황의 `기능 문서 낡음`에 내 기능 문서가 올라오면 실제 구현과 맞는지 보고 기능 문서를 고친 뒤 기준 결정을 올린다. 구현이 아직 기획을 따라가지 못했으면 기능 문서는 그대로 두고 보고한다.
7. 보고: 고친 문서, 반영한 D-번호, 새로 생긴 `확인 필요`.

### 3-3. 새 기획서

1. 기획서 템플릿으로 `Design/분류/기능이름.md`를 만든다. 머리의 기획자·구현 담당·상태·관련 결정을 모두 채운다.
2. 그림은 `Design/images/기능이름_번호.확장자`.
3. `python Tools/check.py --write` → 기능 표에 자동으로 들어간다.

### 3-4. 구현 완료 → 기능 문서

입력: 기능 이름

1. 기획서와 **실제 코드·씬·프리팹**을 확인한다. 조작 키·수치·연결은 코드에서 확인하고 추측하지 않는다. 실행하지 않은 검증은 `미실행`으로 쓴다.
2. 기능 문서 템플릿으로 `Features/기능이름.md`를 쓰고, 머리의 `관련 기획서` 칸에 기획서 링크와 기준 결정(기획서 변경 이력의 가장 큰 D-번호)을 적고, [Features/README.md](Features/README.md)에 한 줄 추가한다.
3. 기획서 상태를 `완료`로 바꾸고 기능 문서를 링크한다 (작업자가 그 기획서의 구현 담당일 때).
4. `python Tools/check.py --write` → 문제 0건.

### 3-5. 회의 안건 만들기

1. `python Tools/check.py --write` 후 `Meetings/현황.md`의 `확인 필요`, `구현 담당 미정`과 결정 로그의 `확인 필요` 상태를 모은다.
2. 급한 순서로 정리한다: 일정에 영향 → 구현을 막음 → 나머지.
3. 안건마다 선택지와 추천안을 붙여 답변으로 보여 준다. 파일은 만들지 않는다.

## 4. 코드 작업

- [Rules/코드컨벤션.md](Rules/코드컨벤션.md)와 [Rules/협업규칙.md](Rules/협업규칙.md)를 따른다.
- 자기 이니셜 폴더(`Assets/<종류>/<이니셜>/`)만 고친다. 클래스는 `namespace <이니셜>` 안에 둔다.
- 남의 영역·`Common`·`ProjectSettings` 수정이 필요하면 요청 문서를 쓴다.
- 구현은 기획서 기준이다. 기획서와 다르게 만들어야 하면 멈추고 사용자에게 묻는다.

## 5. 사람이 AI에게 보내는 요청 문장

필요한 줄을 복사해 붙여 넣습니다.

- **회의 반영:** `TeamWorkflow/AI_지침.md 3-1대로 아래 회의를 반영해 줘. 회의 날짜: YYYY-MM-DD` + 받아쓰기·메모
- **내 기획서 반영:** `TeamWorkflow/AI_지침.md 3-2대로 내(이니셜: ___) 반영 대기를 처리해 줘.`
- **새 기획서:** `TeamWorkflow/AI_지침.md 3-3대로 ___ 기획서를 만들어 줘.` + 내용
- **기능 문서:** `TeamWorkflow/AI_지침.md 3-4대로 ___ 기능의 기능 문서를 만들어 줘.`
- **회의 안건:** `TeamWorkflow/AI_지침.md 3-5대로 다음 회의 안건을 정리해 줘.`

## 6. 개인 AI 설정

저장소 루트의 개인 설정 파일(커밋하지 않음)에 아래 두 줄을 넣습니다. Claude Code는 `CLAUDE.md`, Codex는 `AGENTS.md`입니다.

```text
- 나는 ___ (이니셜)이다.
- 팀 문서·기획·코드 작업은 SteamAttack/TeamWorkflow/AI_지침.md를 따른다.
```

파일을 읽지 못하는 대화형 AI(ChatGPT 웹 등)에는 이 문서 내용을 대화 첫머리에 붙여 넣습니다.

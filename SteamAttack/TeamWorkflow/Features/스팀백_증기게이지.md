# 스팀백(증기 게이지) 사용 가이드

> 대상: 총·수류탄·적 타격·시간 역행·그래픽을 만드는 팀원
> 작성: YPH · 기준: 2단계 총·수류탄 구현(2026-10-01), 화승총 발당 증기 반영(2026-10-15), Unity 6000.6 + URP 17.6
> 화승총 자세한 사용법은 [원거리 무기](원거리무기.md). 수류탄은 게임에서 제외됐습니다(D-028). 수류탄 코드는 NGH `CombatBridge` 정리 후 삭제 예정이라, 이 문서의 수류탄 설명은 `TryConsume` 사용 예시로만 남깁니다.
> 관련 기획서: [증기 시스템](../Design/전투/증기시스템.md) · 기준 결정: 없음 (기획서 재구성 전에 작성)
> 계획서: `Docs/Plans/YPH_계획_20261001_증기게이지.md` (로컬 문서, 저장소에는 없음)

## 1. 한 줄 요약

**스팀백의 증기는 `SteamTank` 하나가 관리합니다. 증기를 쓰거나 채우려면 이 탱크의 메서드만 부르면 되고, 화면(게이지·바늘·배출구)은 알아서 따라 움직입니다.**

**쉬운 비유:** 자동차의 **연료 탱크**와 **계기판**입니다.
- 연료 탱크(`SteamTank`)가 연료 양을 혼자 기억합니다.
- 계기판(게이지·바늘·배출구)은 탱크를 보고 표시만 합니다. 탱크의 연료를 직접 바꾸지 않습니다.
- 엔진(총, 수류탄)은 연료를 달라고 **탱크에 부탁**할 뿐, 연료통을 직접 열지 않습니다.

그래서 총·수류탄 코드는 **게이지 화면을 전혀 몰라도** 됩니다. 반대로 게이지 모델이 바뀌어도 총·수류탄 코드는 안 고쳐도 됩니다.

## 2. 전체 구조

```
  [화승총 한 발]  [받아치기·시간 역행]  [근접 명중 회복]   ← 실제로 쓰는 곳
        │              │               │
    TryConsume      TryConsume       Refill          ← 탱크에 부탁하는 방법
        └──────────────┼───────────────┘
                       ▼
              ┌──────────────────┐
              │  SteamTank   │  ← 증기량의 유일한 주인
              └────────┬─────────┘
        이벤트(소식)로 알림  (탱크는 뷰를 모른다)
     ┌─────────────────┼──────────────────┐
     ▼                 ▼                  ▼
 FillView           NeedleView          VentView
 (증기 높이·색)      (압력 바늘)          (배출구 증기 분출)
     │                 │                  │
 YPH_SteamGauge     NeedlePivot        VentPoint
 .shader            회전               ParticleSystem
```

핵심 규칙 3가지:
1. **값을 바꾸는 길은 탱크의 메서드 3개뿐**입니다. 증기 값은 외부에서 직접 못 건드립니다.
2. **탱크는 뷰를 모릅니다.** 이벤트(`event Action`)로 소식만 던집니다.
3. **뷰는 탱크를 인스펙터로 받습니다.** `Find`나 싱글톤을 쓰지 않습니다.

## 4. 탱크에 부탁하는 3가지 (여기가 제일 중요)

### 4-1. 한눈에 보는 표

| 메서드 | 언제 쓰나 | 돌려주는 값 | 증기가 부족하면 |
|---|---|---|---|
| `bool TryConsume(float amount)` | **화승총 한 발**(10), 받아치기(10), 시간 역행(70)처럼 전부 아니면 안 되는 것 | 성공하면 `true` | 아무것도 소비하지 않고 `false`, 실패 신호 `OnConsumeFailed` |
| `int TryConsumeUnits(float unitCost, int requestedUnits)` | 같은 비용의 낱개를 여러 개(지금은 쓰는 곳 없음. 옛 탄 주머니 충전용) | **실제로 처리한 개수** | 가능한 개수만큼만 소비. 하나도 못 하면 0 |
| `void Refill(float amount)` | **근접 명중**, 받아치기 성공 등으로 증기 회복 | 없음 | (해당 없음) 최대량까지만 참 |
| `bool CanConsume(float amount)` | 소비 **가능한지만** 미리 확인 | 가능하면 `true` | 값·이벤트 변화 없음 |

읽기 전용 값: `CurrentPressure`(현재), `MaxPressure`(최대), `NormalizedPressure`(0~1 비율)

### 4-2. 화승총: 한 발마다 전부 있어야 발사

화승총(`YPH.SteamGun`)은 탄약이 없고 한 발마다 증기 10을 씁니다(D-040). 실제 코드의 흐름은 아래와 같습니다.

```csharp
// SteamGun 안의 흐름을 줄인 것입니다.
public bool CanFire => _state == State.Ready && _tank.CanConsume(_steamCostPerShot);   // 보기만 함

public bool TryFire()
{
    if (!CanFire || !_tank.TryConsume(_steamCostPerShot)) return false;   // 부족하면 아무것도 바뀌지 않음
    // 증기 −10이 끝난 뒤 판정·이펙트
}
```

- 쏠 수 없을 때 입력 코드가 `SteamGun.NotifyFireBlocked()`를 부르면, 증기가 모자란 경우에만 탱크의 실패 신호(`OnConsumeFailed`)가 나갑니다. 증기는 줄지 않습니다.
- 잔량이 0 이하이면 배출구는 멈추고 남아 있던 파티클도 지웁니다. 잔량이 양수지만 비용보다 부족할 때만 작은 실패 분출을 보여 줍니다.
- **화승총 명중으로는 증기가 차지 않습니다.** 증기는 근접 명중과 받아치기 성공으로만 얻습니다([증기 시스템](../Design/전투/증기시스템.md)).

### 4-3. 수류탄: 전부 있어야 제작 (게임에서 제외, 예시로만 남김)

```csharp
if (_steamTank.TryConsume(_grenadeSteamCost))
{
    // 성공: 증기가 이미 줄었음. 수류탄을 지급하세요.
}
else
{
    // 실패: 증기는 그대로. 제작하지 마세요. (양수 잔량이 있을 때만 작은 실패 분출)
}
```

### 4-4. 근접 명중: 증기 회복

근접 명중 회복은 `SteamHitRefill`이 한 곳에서 처리합니다. 지금은 명중 한 번에 10이고, 기획(약공격 +5, 강공격 +10)에 맞춘 구분은 NGH 요청 [근접 적중 약·강 구분](../Requests/진행/YPH_요청_20261015_근접적중약강구분.md) 이후 반영합니다.

```csharp
_steamTank.Refill(_hitRefillAmount);   // 최대량을 넘지 않게 자동으로 잘림
```

- 회복할 때는 **배출구가 분출하지 않습니다.** (게이지와 바늘만 올라감)
- 이미 가득 찼으면 아무 일도 일어나지 않습니다.

### 4-5. 소비 전에 미리 확인하고 싶을 때

```csharp
if (_steamTank.CanConsume(cost)) { /* 버튼 활성화 연출 등 */ }
```

`CanConsume`은 **보기만** 합니다. 증기도 줄지 않고 이벤트도 없습니다. 실제로 쓸 때는 반드시 `TryConsume`을 부르세요. (확인과 소비 사이에 값이 바뀔 수 있습니다)

### 4-6. 잘못된 값을 주면

음수, `NaN`, 무한대는 `Debug.LogError`를 남기고 아무 일도 하지 않습니다. (`TryConsume`은 `false`, `TryConsumeUnits`는 `0`)
- 비용 0 요청은 **성공**이지만 이벤트가 없습니다.
- 빈 탱크에서 양수 요청은 아무리 작아도 **실패**입니다.

## 5. 탱크가 보내는 이벤트 (새 연출을 붙이고 싶을 때)

| 이벤트 | 언제 | 전달값 | 지금 듣는 곳 |
|---|---|---|---|
| `OnPressureChanged(float current, float max)` | **값이 실제로 바뀔 때**마다 (소비·회복 모두) | 현재, 최대 | FillView, NeedleView, VentView(빈 잔량에서 정지) |
| `OnConsumed(float amount)` | **증기를 실제로 썼을 때만** | 실제로 줄어든 양 | VentView |
| `OnConsumeFailed(float requested)` | 유효한 요청인데 **증기가 부족해 하나도 못 썼을 때만** | 요청한 양 | VentView |

**왜 `OnConsumed`가 따로 있나요?** 배출구는 **"쓸 때만"** 쉭 하고 나와야 합니다. 회복할 때나 (나중에) 시간 역행으로 값이 되돌아갈 때는 나오면 안 됩니다. `OnPressureChanged`만 있으면 회복도 똑같이 들려서 구분할 수 없습니다.

**순서:** 소비 성공 시 `OnPressureChanged` → `OnConsumed` 순서로 옵니다.

**새 연출 예시 (경고음, 경고등 등):** 탱크 코드는 건드리지 말고, **이벤트를 구독하는 새 컴포넌트**를 만드세요.

```csharp
public class ABC_SteamWarningSound : MonoBehaviour
{
    [SerializeField] private SteamTank _steamTank;
    [SerializeField, Range(0f, 1f)] private float _warnRatio = 0.2f;

    private void OnEnable()  { _steamTank.OnPressureChanged += HandlePressureChanged; }
    private void OnDisable() { _steamTank.OnPressureChanged -= HandlePressureChanged; }   // ★ 꼭 해제

    private void HandlePressureChanged(float current, float max)
    {
        if (current / max < _warnRatio) { /* 경고음 재생 */ }
    }
}
```

**구독했으면 `OnDisable`에서 반드시 해제**하세요. 안 하면 꺼진 오브젝트가 계속 소식을 받아 오류가 납니다.

## 6. 스팀백을 게임에 넣는 방법

### 6-1. 프리팹 구조

`Prefabs/YPH/YPH_SteamBackpack.prefab` 루트 하나에 컴포넌트 4개가 붙어 있습니다.

```
YPH_SteamBackpack          ← SteamTank + FillView + NeedleView + VentView
 ├ Frame                   (몸체, 임시 Cube)
 ├ SteamVolume             (유리 안 증기 원통, YPH_M_SteamGauge 재질)
 ├ Glass                   (바깥 반투명 유리, 증기보다 살짝 큼)
 ├ NeedlePivot             (바늘 회전 중심)
 │   └ Needle
 └ VentPoint               (용머리 배출구 위치, 파티클)
```

- 세 뷰의 `_tank`는 모두 **루트의 탱크**에 이미 연결되어 있습니다.
- 도형에 Collider는 없습니다. (장식이라 충돌 불필요)

### 6-2. 플레이어에 붙이기

2단계 시험 씬에는 개발용 플레이어와 백팩을 연결했습니다. CHG 실제 플레이어 프리팹 연결은 담당자 합의 후 진행합니다.
1. `YPH_SteamBackpack`을 플레이어 뼈대(등/척추) **자식**으로 놓습니다.
2. 총·수류탄·타격 코드의 `[SerializeField] SteamTank` 칸에 그 프리팹 루트(탱크)를 끌어다 놓습니다.

> 플레이어 프리팹이 `Common`이나 다른 사람 폴더에 있다면 직접 고치지 말고 **담당자에게 요청**하세요. (협업 규칙)

### 6-3. 여러 개 쓰기

백팩을 여러 개 놓아도 **각자 따로 탱크를 가집니다.** 적이나 다른 장치에 증기통이 필요하면 같은 구성을 복사하면 됩니다.

### 6-4. 탱크를 안전하게 읽는 시점

탱크는 `[DefaultExecutionOrder(-100)]`이라 **다른 스크립트보다 먼저 초기화**됩니다. 여러분 코드의 `Awake`/`OnEnable`/`Start`에서 `CurrentPressure`를 읽어도 시작 값이 들어 있습니다.

## 7. 직접 확인하는 법 (테스트 씬)

1. `Scenes/YPH/YPH_CombatTest.unity`를 열고 Play를 누른 뒤 Game 창에 포커스를 둡니다.
2. 시작은 총 `Ready`, 증기 100입니다. 화면 가운데를 기준으로 방향키로 조준합니다.

| 키 | 동작 | 기대 결과 |
|---|---|---|
| 우클릭 홀드 | 조준 | 줌·비네트·줄무늬 |
| 좌클릭 (조준 중) | 화승총 한 발 | 증기 −10. 증기 10 미만이거나 재장전 중이면 발사하지 않음 |
| 좌클릭 (조준 안 함) | — | 발사하지 않음 |
| 방향키 | 좌우·상하 조준 | 초당 90도, 상하 ±60도 |
| `G`, `Tab` | 수류탄 제작·전환 | 시험 리그에만 남은 옛 기능(게임에서 제외, D-028) |

3. 총은 발사 간격 0.25초 뒤 재장전(`Chambering`) 0.5초를 거쳐 다시 `Ready`가 됩니다. 증기 100이면 10발을 쏠 수 있고, 11번째는 발사되지 않습니다.
4. 증기 부족 신호는 탱크 시작 증기를 5로 두고 조준 + 좌클릭으로 확인합니다. 배출구가 작게 분출하고 증기는 5 그대로입니다.
5. 화승총으로 적을 맞히면 피해 20이고 증기는 늘지 않습니다. 표적 HP는 기본 5, 부활은 3초입니다.

> 기존 `YPH_SteamTankTester`와 키 1·2·3 조작은 삭제했습니다. 실제 플레이어 연결 시에는 `CombatTestInput`도 교체해야 합니다. Play에서 바꾼 시험 값은 정지하면 돌아갑니다.

### 7-1. 총 프리팹 연결

`YPH_SteamGunProxy`를 배치한 뒤 총의 `_tank`, `_aimOrigin`(카메라), `_ignoreRoot`(플레이어) 세 곳만 씬 참조로 연결합니다. 몸체·총구·사격선은 프리팹 안에 연결되어 있습니다. 화승총은 명중 회복을 하지 않으므로 `SteamHitRefill`을 연결하지 않습니다.

| 총 색 | 상태 |
|---|---|
| 초록 | `Ready`: 재장전 끝. 증기가 10 이상이면 발사 가능 |
| 빨강 | `Firing`: 발사 간격 대기 |
| 파랑 | `Chambering`: 재장전 중 |

사격선은 0.1초 동안 보이며 적 명중은 초록, 빗맞힘·벽은 노랑입니다. 벽을 맞히면 벽에서 선이 끝납니다. 판정은 카메라에서 시작하고 표시 선만 총구에서 시작합니다.

### 7-2. 수류탄과 조절 위치

- `SteamGrenadeThrower`: 제작 비용·시간, 소지 상한(1 또는 3 등), 투척 간격·속도·위로 주는 속도.
- `YPH_SteamGrenade` 프리팹: `AfterThrow`는 기본 2초 뒤 폭발, `OnImpact`는 처음 닿은 지점에서 폭발. 두 방식 모두 최대 생존시간 안전장치가 있습니다. 자기 몸과의 비행 충돌은 무시하지만 폭발 피해는 받습니다.
- 같은 프리팹의 `Rigidbody`: Mass, Linear Damping, Angular Damping. 빠른 구가 벽을 뚫지 않도록 Continuous Dynamic을 유지합니다.
- `Materials/YPH/YPH_PM_Grenade`: 반발력 0.35, 동적·정적 마찰 0.6. 반발력을 높이면 더 튀고 마찰을 높이면 바닥에서 더 빨리 멈춥니다.
- 폭발 반경은 기본 4m이며 반투명 구 지름은 8m입니다. `YPH_ExplosionFlash`의 시간·불투명도를 조절할 수 있고, 표시 프리팹을 비워도 피해는 처리합니다.

수치에 마우스를 올리면 변화의 영향을 볼 수 있습니다. 시간은 현재 경과시간과 비교하여 Play 중 변경도 반영합니다. 시작 증기는 시작 전에 설정하고, 최대 HP 변경은 다음 부활부터 적용됩니다. 실행 중 소지 상한을 낮춰도 이미 가진 탄·수류탄과 비용을 낸 제작분은 버리지 않습니다.

### 7-3. 자동 검증 재실행

아래는 2026-10-01(탄 주머니 방식) 기준 기록입니다. 화승총 발당 증기 방식의 검증은 [원거리 무기](원거리무기.md) 12번에 있습니다.

로컬 작업 문서 `Docs/Archive/2026-10-01_총수류탄공격/UnityCommands/YPH_CombatCheck.txt`는 새 전투 씬의 Play 모드에서 공식 Unity MCP `Unity_RunCommand`로 실행하는 검사입니다. 상태·태그·피해·기폭 62개, 같은 폴더 `YPH_CombatInputCheck.txt`의 실제 Input System 이벤트 15개, `YPH_CombatVisualCheck.txt`의 충돌 제외·폭발 범위·표시 9개를 통과했습니다. 각 검사는 새로 Play를 시작한 상태에서 실행하고 결과는 같은 이름의 `Check`를 `Result`로 바꾼 파일로 읽습니다. 검사 후 Play를 정지하면 임시 수치·추가 표적이 사라집니다. `Docs/`는 저장소에 포함하지 않는 로컬 검증 자료입니다.

## 9. 내부 동작 (궁금한 사람만)

### 9-1. 게이지는 어떻게 "차 있는 것처럼" 보이나?
- 유리 안에 **원통 메시(`SteamVolume`)** 가 있고, 셰이더가 **높이 아래쪽만** 그립니다. 높이 위쪽은 투명입니다.
- 쉬운 비유: 투명한 병에 **가림막을 올렸다 내렸다** 하는 것입니다. 병 안의 연기는 그대로고, 가림막 높이만 바뀝니다.
- 셰이더의 `_Fill`(0~1)이 가림막 높이입니다. FillView가 압력 비율을 이 값에 넣어 줍니다.
- 증기 질감은 텍스처 없이 **셰이더 안에서 계산한 노이즈**를 위로 흘려보내 만듭니다.
- 높이 범위(`_MinY`, `_MaxY`)는 FillView가 시작할 때 **메시의 로컬 Y 범위에서 자동으로 측정**합니다. 증기 모델을 바꿔도 숫자를 손으로 맞출 필요가 없습니다.

### 9-2. 화면이 부드럽게 움직이는 이유
뷰는 이벤트에서 **목표값만** 바꾸고, `Update`에서 `SmoothDamp`로 따라갑니다. 증기는 **즉시** 줄어도 화면은 0.15초에 걸쳐 내려갑니다. (게임 로직은 화면 속도와 무관)

### 9-3. 성능 메모
- `Update`에서 `new`나 문자열 조합을 하지 않습니다.
- FillView는 `MaterialPropertyBlock`을 재사용합니다. 공유 머티리얼을 복제하지 않습니다.
- 표시값이 목표와 같아지면 `Update`에서 아무것도 하지 않습니다.
- 그 대가로 증기 렌더러는 SRP Batcher 묶음에서 빠집니다. 백팩이 몇 개 없을 때는 문제없지만, 수십 개를 띄우게 되면 다시 확인하세요.

### 9-4. 투명 겹침 순서
증기와 유리가 둘 다 투명이라 그리는 순서가 뒤섞이면 깜빡입니다. 그래서 **증기 큐 3000, 유리 큐 3001**로 순서를 고정했습니다. 재질의 렌더 큐를 바꾸지 마세요.

## 10. 다른 단계 개발자에게

### 10-1. 시간 역행을 만드는 분께 (아직 구현 안 됨)
- **읽기:** `CurrentPressure`로 증기량을 기록할 수 있습니다.
- **쓰기 창구는 아직 없습니다.** 되감을 때 값을 되돌릴 메서드가 필요합니다. 필요해지면 탱크에 `RestorePressure(float)` **한 개만 추가**하면 됩니다.
  - 값을 `0~최대`로 제한해 저장하고 **`OnPressureChanged`만** 발생시킵니다.
  - **`OnConsumed`는 발생시키지 마세요.** 되감는 동안 배출구가 쉭쉭거리지 않게 하려는 약속입니다.
- 탱크는 YPH 담당 파일입니다. **직접 고치지 말고** `SteamAttack/TeamWorkflow/Templates/요청문서_템플릿.md` 양식으로 요청하세요.

### 10-2. 그래픽(3단계)을 만드는 분께: 모델 교체 규칙
임시 도형을 AI 3D 모델로 바꿀 때 아래만 지키면 **코드를 안 고쳐도** 됩니다.

| 항목 | 규칙 |
|---|---|
| 자식 이름 | `Frame`, `SteamVolume`, `Glass`, `NeedlePivot`/`Needle`, `VentPoint` 그대로 |
| `SteamVolume` | **메시 하나**, **로컬 Y가 위아래**, 위아래 뚜껑 있음. 같은 오브젝트에 `MeshFilter` 필요 |
| `Glass` | 증기보다 1~2% 크게. **재질 큐 3001** 유지 |
| `NeedlePivot` | 원점이 **바늘의 회전 중심**. 초기 방향은 NeedleView가 보존 |
| `VentPoint` | 용머리 입구 위치 (파티클 방향이 위) |
| 스케일 | Blender에서 Apply해서 Transform Scale이 1에 가깝게 |

- 바늘이 엉뚱한 방향으로 돌면 NeedleView의 `_rotationAxis`를 (0,0,1)/(1,0,0)/(0,1,0)으로 바꿔 보세요.
- 배출구 파티클은 **Rate over Time = 0**으로 둡니다. 평소엔 안 나오고 코드가 필요할 때만 분출합니다.

### 10-3. 증기를 쓰는 기능을 만드는 분께 체크리스트
- [ ] 탱크를 `[SerializeField] private SteamTank`로 받았다 (`Find`·싱글톤 없음)
- [ ] 한 번에 정해진 양을 쓰는 기능(화승총·받아치기·시간 역행)은 `TryConsume`, `false`면 실행하지 않는다
- [ ] 비용·회복량은 내 코드의 `[SerializeField]`/`ScriptableObject`에 있다 (탱크는 이 수치를 모름)
- [ ] 탱크 값을 직접 바꾸려고 하지 않았다
- [ ] 이벤트를 구독했다면 `OnDisable`에서 해제했다
- [ ] 실제 플레이어 입력 연결 시 `CombatTestInput`을 제거해 입력이 중복되지 않게 했다

## 12. 문제가 생겼을 때

| 증상 | 확인할 것 |
|---|---|
| 게이지가 아예 안 보인다 | 압력이 0이면 정상(비어 있음). 아니면 콘솔의 `LogError`를 보세요. 뷰는 연결이 비면 **스스로 꺼집니다.** `_tank`, `_steamRenderer`가 연결됐는지 확인하세요. |
| 게이지는 줄지 않는데 코드는 소비했다고 한다 | 다른 탱크를 참조하고 있을 수 있습니다. 인스펙터의 연결 대상을 확인하세요. |

| 배출구에서 증기가 안 나온다 | `_ventParticles` 연결 확인. 회복(`Refill`)이나 잔량 0 이하에서는 **안 나오는 게 정상**입니다. |

| 시작하자마자 0에서 차오른다 | 뷰의 `OnEnable` 이후 탱크가 초기화되는 경우입니다. 탱크의 실행 순서(`-100`)를 바꾸지 마세요. |
| 소비했는데 `OnConsumed`가 안 온다 | 비용 0이거나 입력이 잘못된 경우입니다. 이 둘은 이벤트가 없습니다. |
| 실행 중 `_maxPressure`/`_startPressure`를 바꿨는데 반영이 안 된다 | 시작할 때 한 번만 읽습니다. 플레이 전에 바꾸세요. |

## 13. 알려진 한계

- **실행 중 최대 용량 변경은 지원하지 않습니다.** 업그레이드 같은 기능이 필요하면 탱크에 메서드를 추가해야 합니다. (YPH에게 요청)
- **런타임 증기 메시 교체는 반영되지 않습니다.** 높이를 시작할 때 한 번만 측정합니다. 모델은 플레이 전에 연결하세요.
- **시간 역행·CHG 실제 플레이어 연결·정식 아트는 구현되지 않았습니다.** 개발용 플레이어에만 장착되어 있습니다. 실제 연결은 `Requests`의 합의와 후속 어댑터 작업이 필요합니다.
- **광선 버퍼 16개, 폭발 콜라이더 버퍼 32개**의 시제품 한계가 있습니다. 이보다 밀집된 전투는 별도 대응이 필요합니다. 총은 전용 레이어 확정 후 단일 광선 검사로 바꿀 예정입니다.
- **2단계 검증(2026-10-01, 탄 주머니 방식 기준):** Play 자동 검사 86개, 총 5상태의 색·사격선·손 구·폭발 구의 Game 화면을 확인했습니다. 지금 총은 3상태(`Ready`·`Firing`·`Chambering`)입니다. 두 시험 씬에 Missing Script는 없습니다. 새 코드의 컴파일 오류는 없지만, 기존 CHG 파일에서 폐기 예정 `FindFirstObjectByType` API 경고 7개가 남아 있습니다.
- 최종 입력 재검사 15개 통과 후 콘솔 오류는 0개였습니다. Unity 계정 서비스의 `Account API did not become accessible within 30 seconds` 경고 1건은 별도로 관찰됐습니다. 가상 입력 검사 도구에서 발생했던 장치 삭제 후 예약 입력 오류는 예약 해제 순서를 수정한 뒤 재발하지 않았습니다.
- **검증하지 못한 것:** 실행 파일 빌드, Profiler의 GC 측정, 연속 회전 영상에서의 순간 깜빡임, 사람이 직접 키보드를 누르는 시험. 1단계의 기존 기록은 Play 검사 22개·입력 주입 검사·8방향 정지 화면 확인입니다.

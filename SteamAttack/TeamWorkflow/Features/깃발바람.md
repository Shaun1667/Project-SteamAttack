# 기능: 깃발 바람

| 항목 | 내용 |
|---|---|
| 한 줄 설명 | 바람 방향·세기·돌풍에 따라 깃대에 고정된 천이 흔들림 |
| 담당자 | YPH |
| 사용한 AI | Codex |
| 완료일 | 2026-10-30, 검증 범위는 12번 |
| 브랜치 / 커밋 | 미커밋 |
| 관련 기획서 | 없음. 2026-10-30 사용자 직접 구현 요청 |
| 상태 | 구현 완료, 빌드·성능 미검증 |
| 대상 플랫폼 | PC |

## 1. 이 기능은 무엇인가

깃대 쪽 끝은 고정하고 바람이 강할수록 끝부분이 크게 펄럭입니다. 바람 방향이 바뀌면 천이 휘는 방향도 달라집니다. 무풍일 때는 원래 메시 모양으로 돌아갑니다. 실제 천 충돌을 계산하는 물리 시뮬레이션이 아니라 코드로 정점 위치를 계산하는 배경 연출입니다.

## 2. 5분 안에 써 보기

1. `Assets/Scenes/YPH/YPH_BossArena.unity`를 열고 Play합니다.
2. `06_Statues_And_Flags` 아래 깃발 4개를 확인합니다.
3. `YPH_FlagWind`의 Y 회전을 바꾸면 바람 방향이 바뀝니다.
4. WindZone의 Main을 0으로 바꾸면 멈추고, 1 이상으로 높이면 더 크게 흔들립니다.

## 3. 테스트 조작법

전용 키는 없습니다. Play 중 Inspector에서 WindZone 값을 조절합니다. Play 중 변경한 값은 종료 시 복원되므로 영구 조정은 편집 모드에서 합니다.

## 4. 어떻게 만들어졌나 (구조)

에셋 경로는 `Assets/` 기준입니다.

| 경로 | 역할 |
|---|---|
| `Scripts/YPH/FlagWind.cs` | `namespace YPH`. 바람을 읽고 천 정점·법선·경계를 갱신 |
| `Arts/Models/YPH/YPH_BossArena/BossArena_Blockout/Generated/Flag_assembled.prefab` | `Plane`에 FlagWind 추가 |
| 같은 Generated 폴더의 `FlagCloth_Wind.asset` | 원래 천과 같은 153정점·256삼각형·UV를 가진 읽기 가능한 메시 사본 |
| `Scenes/YPH/YPH_BossArena.unity` | Directional WindZone 한 개와 깃발 4개의 참조 |

Play에 들어가면 깃발마다 메시를 복제합니다. 원본 메시를 수정하지 않습니다. 왼쪽 고정 영역은 그대로 두고 바람에 따른 곡률과 두 종류의 파동을 나머지 정점에 적용합니다. 각 깃발 위치에서 서로 다른 위상 값을 계산하므로 완전히 같은 박자로 흔들리지 않습니다. 컴포넌트를 끄면 원본 메시를 다시 연결하고, 오브젝트가 제거되면 복제 메시를 해제합니다.

## 5. 왜 이렇게 만들었나 (설계 이유)

기존 천에 충분한 정점이 있어 리깅·Cloth 패키지 추가 없이 구현했습니다. 깃대·FBX·재질·UV는 유지합니다. 별도 읽기 가능한 천 메시를 사용하므로 깃대까지 FBX의 Read/Write를 켤 필요가 없습니다.

## 6. 인스펙터 값 설명

| 대상 / 값 | 기본값 | 의미 |
|---|---|---|
| WindZone / Main | 0.85 | 바람 세기. 0이면 정지 |
| WindZone / Turbulence | 0.5 | 작은 잔물결의 강도 |
| WindZone / Pulse Magnitude | 0.25 | 돌풍의 추가 세기 |
| WindZone / Pulse Frequency | 0.35 | 초당 돌풍 반복 횟수 |
| FlagWind / Wind Zone | 씬의 YPH_FlagWind | Directional 방식만 지원. 연결 오브젝트를 비활성화하면 정지 |
| FlagWind / Wind Direction, Strength | `(1,0,0.35)`, 0.8 | WindZone을 연결하지 않았을 때 기본 월드 바람 |
| FlagWind / Amplitude | 0.075 | 너비에 대한 물결 크기 비율 |
| FlagWind / Frequency | 1.6 | 기본 초당 물결 횟수 |
| FlagWind / Pinned Width | 0.02 | 로컬 X 최소값 쪽 고정 너비 비율 |

## 7. 내 코드에서 쓰는 법

별도의 공개 API는 없습니다. 연결한 WindZone의 `windMain`, `windTurbulence`, `windPulseMagnitude`, `windPulseFrequency`와 Transform 회전을 변경하면 다음 Update에서 반영됩니다. 바람이 불어가는 방향은 WindZone의 로컬 +Z 축입니다.

## 8. 확장하는 법

다른 깃발에는 읽기 가능한 XY 평면 메시의 MeshFilter와 MeshRenderer에 FlagWind를 붙입니다. 로컬 X 최소값이 깃대 쪽이어야 합니다. 메시를 재활용해도 실행 중 복제본을 쓰므로 서로 변형되지 않습니다. 현재 양면 Lit 재질을 유지합니다. 다른 축·본 리깅 메시 지원은 포함하지 않습니다.

## 9. 협업 가이드

스크립트·모델 사본·프리팹·시험 씬은 YPH 소유입니다. 다른 담당자의 씬·프리팹은 수정하지 않았습니다. 씬 저장 시 Unity가 기존 Light·LODGroup의 직렬화 버전을 갱신했으나 조명 값과 LOD 기준값은 변경하지 않았습니다.

## 10. 의존성과 준비물

Unity MeshFilter, MeshRenderer, Directional WindZone만 사용합니다. 추가 패키지는 없습니다. 천의 정적 배칭은 사용하지 않습니다.

## 11. 성능 기록

현재 4개 × 153정점을 매 프레임 갱신합니다. 정점 배열과 컴포넌트 참조는 재사용하며 매 프레임 검색하지 않습니다. FPS·GC·GPU 시간은 미측정입니다. 깃발을 대량 배치할 때는 CPU 메시 변형 비용을 측정해야 합니다.

## 12. 검증 결과

현재 보스전 씬의 실제 Update 기반 Play 검사에서 이동, 고정점 오차 0, 무풍 원형 복원, 바람 방향 반전, 비활성 시 원본 복구·재활성 연결을 확인했습니다. 두 번의 Play(162·142프레임)에서 실행 오류 0건, 최대 이동은 약 0.42m였습니다. 무풍·바람 화면을 직접 비교했습니다. 기존 씬의 미저장 상태를 유지하고 Edit 모드로 복귀했습니다. 기록과 캡처: `Docs/Archive/2026-10-30_FlagWind/`.

## 13. 알려진 문제와 앞으로 할 일

천의 자체 충돌·깃대/주변 구조물 충돌·찢어짐은 계산하지 않습니다. 방향은 깃발의 수평면에 투영하며 Sphere WindZone은 지원하지 않습니다. 강한 역풍은 120도 범위로 제한합니다. 무풍 상태는 원래 펼쳐진 메시이며 중력으로 늘어지는 물리 동작은 없습니다. 빌드·다수 깃발 성능 검사는 미실행입니다.

## 14. 용어

- 정점: 천의 모양을 만드는 점입니다.
- 위상: 물결이 시작되는 시점의 차이입니다.
- WindZone: Unity에서 바람의 방향과 세기를 설정하는 컴포넌트입니다.

## 1. 이 기능은 무엇인가

플레이어를 발견하면 다가와 찌르기 또는 내려치기를 고릅니다. 찌르기는 받아칠 수 없고, 내려치기는 창끝의 동심원이 붉을 때 Ctrl로 받아칠 수 있습니다. 받아치기에 성공하면 적이 잠시 멈춰 강공격을 넣을 기회가 생깁니다. HP가 0이면 몸은 남지만 길을 막거나 더 맞지 않습니다. 쓰러지는 모션이 끝나면 누운 자세로 남습니다.

## 2. 5분 안에 써 보기

1. `Assets/Scenes/YPH/YPH_MainPlayerTest.unity`를 엽니다.
2. 플레이어 시작점 앞의 `YPH_MutantSoldier_1`, `YPH_MutantSoldier_2`를 확인합니다.
3. Play 후 접근해 피해와 동심원을 확인합니다.
4. 설정은 `Assets/Prefabs/YPH/Enemy/YPH_MutantSoldier.prefab` 루트에서 바꿉니다. 씬 인스턴스에는 배치만 덮어씁니다.

## 3. 테스트 조작법

### 3-1. 게임 조작 키

| 입력 | 동작 | 조건·주의 |
|---|---|---|
| WASD | 이동 | 기존 NGH 플레이어 |
| F | 발도·납도 | 환도 선택 상태 |
| 좌클릭 | 약공격 | 피해 10, 다섯 번 적중하면 HP 50 소진 |
| 좌우 동시 클릭 | 강공격 | 현재 플레이어 구현의 입력. 피해 20 |
| Ctrl | 받아치기 | 내려치기 동심원의 붉은 구간 ±0.1초 |

입력은 기존 Input System·NGH 플레이어와 YPH `ParryController`를 사용합니다. E1에서 플레이어 코드·애니메이터·프리팹은 변경하지 않았습니다.

### 3-2. 테스트 전용 키 (디버그)

E1에서 추가한 키는 없습니다. 기존 개발 키는 [적 AI 문서](적AI.md#3-테스트-조작법)를 참고합니다.

### 3-3. 테스트 시나리오

| 순서 | 확인할 것 |
|---|---|
| 접근 | 발견·추적 후 공격, 일반 공격이 더 자주 나옴 |
| 피격 | 일반 10, 강공격 15 감소 |
| 받아치기 | 일반 공격은 실패, 내려치기는 창끝 동심원·공격 취소·경직 |
| 처치 | 몸과 창 유지, 충돌·피격·체력바 꺼짐, 5초 뒤에도 부활 없음 |
| 재실행 | Play를 끝내고 다시 시작해 같은 동작 확인 |

## 4. 어떻게 만들어졌나 (구조)

### 4-1. 만들거나 고친 파일

아래 경로는 `Assets/` 기준입니다.

| 경로 | 변경 | 역할 |
|---|---|---|

| `Materials/YPH/Enemy/YPH_M_MutantSoldier.mat` | 신규 | 몸·창이 공유하는 회청색 Lit 재질 |
| `Prefabs/YPH/Enemy/YPH_Spear.prefab` | 신규 | 전체 길이 2.0m의 충돌 없는 창·끝 위치 |
| `Animations/YPH/Enemy/MutantSoldier/YPH_MutantSoldier.controller` | 신규 | 기존 상태·파라미터·전환을 유지하고 클립 7개 연결 |
| `Prefabs/YPH/Enemy/YPH_MutantSoldier.prefab` | 신규 | 기존 MeleeEnemy 구성과 확정 수치 |
| `Scenes/YPH/YPH_MainPlayerTest.unity` | 수정 | MeleeEnemy_R1을 새 프리팹 두 개로 교체 |

### E1-b 모델·모션 연결

모델은 `Arts/Models/YPH/Enemy/MutantSoldier/HumanM_Model.fbx`, 모션은 `Animations/YPH/Enemy/MutantSoldier/`에 있습니다. 모두 Humanoid이며 모션은 모델의 Avatar를 공유합니다. 루트 회전·Y·XZ Bake Into Pose를 켰습니다.

| 상태 | FBX | 길이(초) | 반복 | 파일 크기(MB, 10⁶바이트) |
|---|---|---|---|---|
| Locomotion 0 | HumanM@CombatIdlePolearm01 | 1.333333 | 켬 | 0.580 |
| Locomotion 0.5 | HumanM@Walk01_Forward | 0.800000 | 켬 | 0.481 |
| Locomotion 1 | HumanM@Run01_Forward | 0.600000 | 켬 | 0.444 |
| Attack | HumanM@AttackPolearm01 | 1.366667 | 끔 | 0.586 |
| HeavyAttack | HumanM@AttackPolearm03 | 1.366667 | 끔 | 0.586 |
| Parried | HumanM@Stun01 | 2.666667 | 끔 | 0.826 |
| Die | HumanM@CombatDeath03 | 1.166667 | 끔 | 0.549 |

공격 이벤트는 각각 30FPS의 16·17프레임에 `OnAttackHit` / String `Attack`·`HeavyAttack`으로 넣었습니다. FBX Importer의 이벤트 시간은 0~1 비율이므로 Inspector에 입력하는 값과 가져온 AnimationClip의 초 값을 혼동하지 않습니다. 모델은 0.936MB이고 모션 7개 합계는 4.051MB입니다.

### 4-2. 클래스 관계

`EnemyAI`가 판단하고 `EnemyMotor`가 이동, `EnemyMeleeAttack`이 공격, `EnemyAnimatorLink`가 Animator 파라미터를 전달합니다. `EnemyHealth`가 사망을 알리면 AI가 멈추고 `EnemyDamageRelay`와 `EnemyHpBar`가 피격 수신·체력바를 끕니다. 새 클래스는 없습니다. 공통 구조는 [적 AI](적AI.md#4-어떻게-만들어졌나-구조)를 참고합니다.

### 4-3. 동작 흐름

1. 감지 → 추적 → 일반/강공격 선택.
2. `EnemyAnimatorLink`가 `OnAttackHit` 이벤트 시각을 읽습니다. 찌르기는 0.533초, 내려치기는 0.567초 뒤에 기존 타이머로 판정합니다. 실제 이벤트 수신은 피해를 다시 주지 않습니다.
3. 강공격 예고 → `IParryTarget` → 플레이어의 기존 받아치기 → 공격 취소·경직.
4. HP 0 → AI 중단 → `hideDelay` 뒤 렌더러는 남기고 충돌체를 끄며 Rigidbody를 kinematic으로 만듭니다.
5. `respawnDelay=0`이므로 자동 부활하지 않습니다. 명시적인 `Revive`·풀 생명주기는 기존처럼 복구할 수 있습니다.

### 4-4. 프리팹·씬 구성

- 루트: 기존 MeleeEnemy의 컴포넌트·태그 `Enemy`·레이어 `Default`를 유지합니다. 원거리 부품은 없습니다.
- `Body/HumanM_Model`: 유효한 Humanoid Avatar와 기존 Controller. Root Motion 꺼짐. 캡슐 메시와 예전 빈 Animator 오브젝트를 제거했습니다. 모델 발을 루트 높이 0에 맞추고 CapsuleCollider 높이 1.817905m·중심 Y 0.908953m로 맞췄습니다.
- 모델의 오른손 뼈 아래 `RightHandSocket/YPH_Spear/ParryPoint`: 창끝. AI의 `_parryPoint`에 직접 연결합니다. 창 자식에는 Collider가 없습니다.
- `Locomotion`: Speed 0/0.5/1의 대기·걷기·뛰기 Blend Tree. `Attack`, `HeavyAttack`, `Parried`: 트리거 진입·Exit Time 복귀. `Die`: 최우선 진입·나가는 전환 없음.
- 파라미터는 `Speed`, `InCombat`, `Attack`, `HeavyAttack`, `Parried`, `Die` 여섯 개입니다. 전환 시간은 Unity 기본값입니다.
- 기존 `Merge_TestArea/Enemy`는 공격 부품 없는 별도 오브젝트로 유지합니다. Legacy 씬은 복제 기준으로만 읽었습니다.

## 5. 왜 이렇게 만들었나 (설계 이유)

기존 공격 타이머와 받아치기 규약에 FBX 모션의 타격 시각만 연결했습니다. E1-b의 코드 수정은 없습니다. 새 사망 옵션의 기본값을 끄고 프리팹에서만 켜서 기존 시험 적의 숨김·부활 설정을 유지합니다. 창을 중첩 프리팹으로 두어 이후 모델 교체와 손뼈 연결 때 경로·기능을 재사용합니다.

## 6. 인스펙터 값 설명

| 컴포넌트 / 값 | 이 프리팹 | 영향 |
|---|---|---|
| EnemyHealth / maxHp | 50 | 쓰러질 때까지 필요한 총 피해 |
| EnemyHealth / _keepBodyOnDeath | true (코드 기본 false) | 켜면 사망 뒤 몸을 남김. 충돌은 항상 꺼짐 |
| EnemyHealth / respawnDelay | 0 | 자동 부활 안 함. 양수면 몸 남기기와 관계없이 부활 |
| EnemyMeleeAttack / _attackDamage, _heavyDamage | 10, 15 | 플레이어 피해 |
| EnemyMeleeAttack / _heavyChance | 0.3 | 공격 주기마다 강공격을 고를 확률 |
| EnemyMeleeAttack / _heavyEnabled, _heavyParryable | true, true | 강공격·받아치기 사용 |
| EnemyMeleeAttack / _kickEnabled | false | 킥 미사용 |
| EnemyAI / _parriedStunTime | 1.8초 | 받아치기 후 멈추는 시간 |
| 일반/강 판정까지 | 저장값 0.4 / 1.62초 | 이벤트가 우선하므로 실제로는 0.533333 / 0.566667초 |
| 일반/강 시작 거리 | 1.8 / 4.5m | 몸 중심 기준 공격 시작 거리 |
| 일반/강 후딜레이 | 저장값 1.2 / 1.9초 | 일반은 1.2초. 강공격은 기존 코드가 클립의 남은 길이 0.65초로 계산 |
| 배회 반경·속도 | 6m / 1.5m/s | 기존 MeleeEnemy 값 |
| 감지·놓침 거리·추적 속도 | 8m / 12m / 3.5m/s | 기존 MeleeEnemy 값 |

나머지는 복제한 MeleeEnemy 값을 유지합니다. 창 전체 2.0m는 사용자 지정이며, 자루 1.75m+창끝 0.25m입니다. 자루 지름 0.06m, 창끝 폭 0.12m, 색 `#667F8C`, 손잡이는 모델의 오른손 뼈를 따르며, E1-b에서 대기 자세와 내려치기 접지에 맞춰 위치·회전을 보정했습니다. 창 프리팹 자체의 크기는 바꾸지 않았습니다. 배치는 플레이어 시작점 기준 좌우 2m·앞 6m입니다.

## 7. 내 코드에서 쓰는 법

### 7-1. 공개 API

새 공개 API는 없습니다. 피해는 기존 `EnemyDamageRelay` / `EnemyHealth.TakeDamage`, 받아치기는 `IParryTarget`, 복구는 `Revive` / `IPoolable`을 사용합니다.

### 7-2. 사용 예시

씬에 변이 포졸 프리팹을 배치하고 플레이어의 태그가 `Player`인지 확인합니다. 코드 예시는 [적 AI](적AI.md#7-내-코드에서-쓰는-법)에 있습니다.

### 7-3. 이 기능에 연결하려면

기존 `EnemyAttackHitbox` 참조와 창끝 `_parryPoint`를 유지합니다. HP를 `Damageable`과 별도로 직접 관리하지 않습니다. 주 체력은 `EnemyHealth`가 소유합니다.

## 8. 확장하는 법

모션을 교체할 때 Humanoid Avatar·Root Transform Bake Into Pose·Loop·타격 이벤트를 함께 확인합니다. 손 IK와 패키지의 추가 Animator 레이어는 사용하지 않습니다. 사거리·속도·전환 조정은 기획 확인 뒤 적용합니다.

## 9. 협업 가이드

프리팹·AI는 YPH 담당입니다. Main·BossArena 배치는 NGH의 [기존 적 교체 요청](../Requests/진행/NGH_요청_20261015_기존EnemyAI적교체.md)으로 진행합니다. E1 작업에서는 NGH 플레이어·스크립트·애니메이터, Main·BossArena·Legacy 씬을 수정하지 않습니다.

## 10. 의존성과 준비물

기존 YPH 적 AI·받아치기, NGH `Damageable`·`ObjectPool`·플레이어, CHG 공격 판정 프리팹, URP Lit 재질을 사용합니다. 새 UPM 패키지는 없습니다. 사용자가 제공한 Spearman.unitypackage에서 모델 1개와 모션 7개만 가져왔습니다. 원본 FBX와 GUID를 유지하고, 원본 패키지의 Controller·스크립트·데모 씬은 가져오지 않았습니다.

## 11. 성능 기록 (PC, 목표 60FPS)

FPS·GC·다수 적 부하는 미측정입니다. 이번 검증은 두 적의 기능 검사입니다.

## 12. 검증 결과

### E1-a 검증 기록 (클립 연결 전)

- 근접 수신 경로의 피해 10×5 → HP 0, 사망 후 몸·창 유지, 모든 충돌체 꺼짐, 피격 수신·체력바 꺼짐, 추가 피해 무시, 5초 이후 부활 없음: Play 통과.
- 옵션을 끈 경우 몸 숨김·5초 부활, `Revive`·`OnDespawned`·`OnSpawned` 복구: Play 통과.
- 두 번의 Play 진입 통과. 자연 전투 30회 일반/강공격 20/10, 실제 HP 감소 10/15 확인.
- 실제 Ctrl: 일반 공격 거부·내려치기 성공. 흰색·붉은 동심원 관측, 창끝 Transform 연결 확인. 경직 1.798초, 받아치기 후 실제 좌우 클릭 강공격 피해 20·적중까지 0.626초.
- 저장된 프리팹 수치·참조, 6개 파라미터·5개 상태·빈 Blend Tree·모션 0개·창 전체 2.0m 검사 통과.
- 콘솔 조회에서 기존 배경 메시의 재질 초과 경고가 200건 반환됨(도구 반환 상한). 새 적의 렌더러는 각 재질 1개. 전체 경고 0건은 충족하지 못함.
- 최종 오류·예외 조회 0건, Animator 오류·경고 필터 조회 0건. `YPH_MainPlayerTest` 편집 모드·미저장 변경 없음으로 종료. 문서 검사 문제 0건.
- YPH 로컬 증거: `Docs/Archive/2026-10-16_E1변이포졸/UnityCommands/`.

### E1-b 검증 기록

- 저장된 전투 수치·창 길이 2m 유지. Controller는 Motion 참조를 제외한 파일 내용이 E1-a와 동일합니다. 클립 7개·Animator·오른손·창끝 참조 검사 통과.
- 첫 Play 자연 전투 30회: 일반 25 / 강공격 5. 플레이어 HP 감소 10 / 15 확인.
- 실제 Ctrl 성공, 일반 공격 거부, 흰색·붉은 동심원 관측. 경직 1.798569초, Ctrl 이후 좌우 동시 클릭 강공격 피해 20·적중까지 0.625511초.
- 실제 피해 순간 Animator 재생 시각: 일반 0.528966~0.533381초(7회), 강공격 0.562890~0.563706초(2회). 지정 이벤트와 차이 0.005초 미만.
- 피해 수신 API로 10×5 적용 → Die 끝 자세, 골반 높이 약 0.111m, 충돌·추가 피격·체력바 꺼짐. 5.5초 후에도 부활 없이 같은 누운 자세 유지.
- 두 번째 Play에서도 실제 Ctrl 성공·강공격 피해 20(적중까지 0.628069초)·사망 후 5.5초 자세 유지 검사 통과.
- 최종 콘솔 오류·예외 0건, Animator 경고 0건. 전체 조회에는 기존 배경 메시 재질 초과 경고 200건(도구 반환 상한)이 남습니다.

## 13. 알려진 문제와 앞으로 할 일

- 경직 모션은 2.666667초이고 AI 경직은 1.8초입니다. 기존 Parried → Locomotion 전환은 Exit Time 0.75·Duration 0.25이므로 약 2초부터 복귀합니다. 실제 경직 종료 순간에도 Parried 상태임을 확인했습니다. 전환·속도·코드는 요청 범위에 따라 유지했습니다.
- 내려치기 판정까지 0.567초, 동심원이 겹칠 때까지 약 0.417초입니다. 기존 0.8초 수축 시간보다 짧아 중간 크기에서 예고를 시작합니다. 클립 속도를 임의로 낮추지 않았습니다.
- 보행·주행의 접지 구간 클립 표본과 기존 속도를 비교하면 잔여 발속도 평균 약 0.499 / 0.463m/s입니다. 고정 속도 직진 가정의 추정이며 실제 회전·혼합은 미반영입니다. 루트 이동 0m·반복 경계 일치는 확인했습니다. 재생 배율을 임의로 바꾸지 않고 [조정 요청](../Requests/진행/YPH_요청_20261016_변이포졸보행재생속도.md)에 기록했습니다.
- 사거리·후딜레이·경직은 계획서 임시값입니다. 창 소품의 모양이 실제 타격 상자와 일치한다는 뜻은 아닙니다. E1-b 이후 실측으로 조정해야 합니다.
- 실행 파일 빌드·사람의 수동 조작 평가는 미실행입니다. 피해 10×5 검사는 근접 피격 수신 API로 실행했으며 좌클릭 다섯 번을 별도로 측정한 결과는 아닙니다. 통과 가능 여부는 모든 충돌체가 꺼짐을 검사했습니다.
- 기존 배경의 `Mesh ... has more materials (2) than submeshes (1)` 경고는 범위 밖으로 수정하지 않았습니다.
- E1-a 작업 시작 해시와 비교해 `ProjectSettings/URPProjectSettings.asset`, NGH `NotoSerifKR SDF Hanja (Dynamic).asset`, NMJ `NMJ_HudGlyphs SDF.asset` 변화가 감지됐습니다. 직접 수정한 파일은 아니며 다른 작업을 보존하기 위해 되돌리거나 커밋하지 않았습니다. URP 설정은 Git 내용 차이 없이 줄 끝 형식만 달랐습니다.
